플레이어는 현재 selected Issue, current CaseTheory, ReviewWorkProduct, Investigation 결과와 newly acquired SourceMaterial을 바탕으로

→ legal research

## Implement

The player must be able to:

1. inspect the active Issue and current CaseTheory

3. assign / execute / complete legal research work

   - source exists

   - Issue

## Legal Research Rules

LegalSource existence does not mean the player has found it.

LegalSource discovery does not mean it has been reviewed.

Review does not mean the source was correctly understood.

Discovery must materialize an immutable LegalSourceDiscoveryEvent. Review must materialize a separate immutable LegalSourceReviewEvent with exact LegalSource ID/version/scope and research lifecycle provenance. A read/open/query creates neither event.

A RecordedLegalExtraction must reference exactly one reviewed LegalSource ID/version and non-empty exact reviewed scope. A RuleStatement requires one or more RecordedLegalExtraction references and preserves their transitive source/version/scope provenance.

An InterpretationCandidate materializes explicitly from RuleStatement reference(s) and must remain an analysis candidate rather than hidden truth.

IssueAnalysis materializes only through an explicit command after the referenced research Task is complete and must preserve:

- Issue reference
- research task / work provenance
- reviewed LegalSource references
- RecordedLegalExtraction references
- extracted RuleStatement references
- relevant InterpretationCandidate references
- content / source versions
- actor / team / matter / stage provenance

No hidden "correct law oracle" may be queried by the player or UI.

Do not create:

- winning authority
- best precedent score
- universal legal strength score
- automatic correct interpretation flag

---

## Argument Creation and Selection Rules

Argument creation and selection are separate explicit commands.

An Argument must preserve:

- active Issue
- current CaseTheory version
- relevant ReviewWorkProduct(s)
- relevant InvestigationResult / acquired SourceMaterial provenance
- IssueAnalysis
- supporting LegalSource version/exact-scope, RecordedLegalExtraction, RuleStatement and InterpretationCandidate refs
- known gaps / assumptions / challenges where relevant
- actor / team / matter / stage
- stable never-reused Argument ID
- authored argument key / formulation
- optional parent Argument lineage for revision
- research task / assignment / execution / completion provenance
- content version
- creation event / event order

Argument creation must use an authored argument recipe and reject stale CaseTheory, missing/mismatched provenance, un-authored combinations and duplicate identity atomically. Candidate interpretation or IssueAnalysis creation must not auto-create an Argument.

Selection materializes an immutable ArgumentSelectionEvent referencing the existing Argument, active Issue, current CaseTheory version, selector actor/team/matter/stage, content version and event order. Re-selection appends history; current strategic state is derived from the latest valid selection event.

Do not introduce a canonical Strategy object. Argument selection must NOT create:

- Strategy
- StrategicNarrative
- Submission
- CourtRecord
- CourtRecordSnapshot
- CourtFactFinding
- FinalAdjudicationResult
- Judgment

## Meaningful Choice Requirement

The player must have at least two meaningfully different authored Argument choices.

Different choices must preserve different semantic provenance.

They do not need to produce a judgment yet.

The purpose is to make the player's current Argument selection observably different without designing its later procedural effect.

Avoid fake choices where two UI buttons produce Arguments with the same semantic provenance.

## Required Regression Cases

At minimum test:

### Research workflow

- valid research assignment
- assigned research has no Execution / Completion
- valid research execution
- explicit completion required
- insufficient work rejected
- invalid actor/team rejected
- dependency not satisfied rejected
- duplicate task / assignment / execution / completion identity rejected
- failed command leaves authoritative state unchanged

### Legal source boundaries

- undiscovered LegalSource does not appear in player projection
- discovered but unreviewed LegalSource does not produce RuleStatement
- reviewed LegalSource may support authored RuleStatement extraction
- source existence ≠ discovery
- discovery ≠ review
- review ≠ correct application
- exact source/version/scope provenance preserved
- unauthorized source/scope blocked

### Analysis boundaries

- IssueAnalysis requires valid Issue and completed research basis
- wrong/plausible authored interpretation remains analysis, not truth
- Argument requires valid provenance
- creating Argument does not alter SourceAssertion or CourtFactFinding
- no hidden correct-law query is exposed

### Argument creation and selection

- valid authored Argument creation
- Argument requires current CaseTheory and valid IssueAnalysis / InterpretationCandidate / RuleStatement / extraction / source basis
- invalid/stale/un-authored Argument creation is rejected atomically
- valid Argument selection creates a new immutable selection event
- re-selection preserves prior Argument and selection history
- selection creates no canonical Strategy object
- stale base update rejected
- two authored choices create observably different Argument provenance

### State safety

- returned projections are deep copies
- repeated read/query creates no new domain events
- deterministic command sequence produces deterministic state/event order
- VS-001 behavior remains intact
- VS-002 behavior remains intact
- VS-003 behavior remains intact
- no CourtRecord exists after VS-004
- no CourtFactFinding exists after VS-004
- no Judgment exists after VS-004

All previous regression suites must remain passing.

New VS-004 regression runner must return nonzero on failure.
