## Snapshot / Provenance / Evaluation Rules

SubmissionService copies the exact resolved finalized version's entire ordered factual_basis_refs array, including empty arrays and nested typed/version/scope/provenance fields. No filtering, caller basis, source lookup, reconstruction or injected approval support. Authoritative entry, entry-created journal payload, command return and existing record projection preserve equivalent content with nested-copy isolation. Existing records/events remain immutable. A historical entry lacking this field supplies no EvidenceUse; otherwise valid eligibility is unchanged. Adjudication never queries FinalizedDocument or DraftWorkProduct to recover basis.

Capture includes every existing entry at command start satisfying DEC-030's exact matter/stage, valid materialization event, accepted_for_record result, canonical VS-005 inclusion rule and agreeing preserved entry/event/result/attempt/document-ID/version provenance. Derive membership in immutable CourtRecord event order. Caller omission, injection or reordering is impossible. Corrupted cross-references fail atomically. Later materialization cannot change earlier snapshots. Capture creates no finding.

Evaluation resolves only snapshot-listed entries and revalidates preserved cross-references. It reads no private SourceMaterial, ReviewWorkProduct, InvestigationResult, Argument, DraftWorkProduct, FinalizedDocument, ActualStateRecord or hidden content to repair missing support. A successful command atomically appends exactly one trace, one finding and their events. Any failure leaves complete authoritative state and journal unchanged. Fresh IDs are required for reevaluation; history is never overwritten. Reads/redraws are pure. Same content/commands produce semantically deterministic membership, EvidenceUse, outcomes, reasons and event order.
