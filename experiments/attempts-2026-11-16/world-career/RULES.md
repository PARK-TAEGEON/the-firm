## 뉴스·순위

- 순위는 영업 로펌만: 수입순, 처리량순, 달성률100×(달성+5)/(처리+10)(20건 이상). 동률ID순. 전략별 선두는 해당 전략의 수입1위.
- 메타데이터: eventId/eventIds, 주/연/月, type, category, 중요도1..5, firmIds/personIds/specialties, title/body. category는 순위/대형사건/판례/인사/시장/내 로펌.
- 주요인물·현재 상위10로펌 관련 인사와 지정 관심 인물/로펌은 개별 후보. 낮은 중요도 인사는 월말 요약하며 원본 참조를 유지한다. 요약 시점 이미 폐업한 로펌은 관련 로펌 목록에서 제외한다. 과거 원장은 지우지 않는다.
- 2월 순환 기사는 실제 해당 주 전체 순환 이벤트 수를 표시. 무소속 변호사와 공직을 이벤트 당시 role로 구분. 피로 회복은 번아웃 복귀에만 표기, 육아/파견은 기간 종료. 1월 초기화 문구는1월에만, 매출0 선두 헤드라인 없음.
- 서비스 종결마다 대형 관심도2/10,000, 가상 판례 공보1/10,000를 중앙 RNG로 기록. 대형사건은 실제 서비스 기록 참조, 승패 주장은 없음. 판례는 KO 템플릿의 fixture 공보로 명시하며 법적 추론/판례 효력/규칙 수정자는 없다.
- 개업 중요도4, 대형 이적(출발 또는 도착15명 이상)5. 일반 인사/시장 중요도는 NEWS.types. 판례 공보/대형 관심도5. 원본 판정이 없는 승패를 뉴스가 발명하지 않는다.
- 연말10대: 완료된 해 후보에서 월간 요약/주간 통계 묶음 제외, 같은 personId 중복 금지. 개업과 대형 이적을 각1건 우선 확보, 나머지는 중요도/발생주/기록ID 순으로 채운 뒤 같은 순서 정렬. 해당 범주 후보가 없으면 강제로 만들지 않는다.
- 주간1면: 최근4주, 전주 선정 ID 제외, 통계 기사(주간 시장·처리 요약·월순위·연말순위·월간 인사 요약) 최대1건. 관련도(내로펌100/라이벌30/관심인물30/전문10)→중요도→최신순. 분류당3건 우선, 최대7. 5건을 선호하지만 강한 제약과 실제 기사 부족 때문에1~4건도 허용한다. 다음 주 제외만 보장하며2주 전 기사는 재선정 가능하다.
- 기사/선별은 읽기 전용. 모든 원본은 해당 시점까지의 기록이고 미래 사건을 끌어오지 않는다. 수치/문장 길이 UI 예산은 테스트하지 않는다.

## 검증과 보고

- node world/run.js --years 10 --seed 1: news.md/stats.json 생성. years1..100, seed0..4294967295 정수. 잘못된 인자는 기존 출력을 보존한다. 파일 두 개의 파일시스템 트랜잭션은 미구현.
- node world/report.js:20년×seed1/2/3. audit.js는 인물/로펌 생애 원시 이벤트를 재생하며 year_closed 집계를 사용하지 않는다. weekly_census는 관측 시점으로만 사용한다. 신입 채용은 해당 연도 유입 인물 집합의 중복 없는 채용수다.
- 무소속≤10%, 개업2~4%, 로펌28~42, 이직7~10%, 전체휴직3~5%는60개 연도 각각 확인. 추세는 마지막5년 평균과 첫5년 평균 비교, 유한 인구 반올림을 위해0.5%p 허용. 모든 시드/무한 기간 보장 아님.
- 기본10년 성능 목표3초, 확대3,000변호사 시험은 별도 실제 시간 기록. 서비스 snapshot·기사 투영·JSON/파일 기록 시간을 구분한다. report 실행은 복잡한 모든 테스트와 동시 측정하지 않는다.
- out/는 Git 제외. 원시 이벤트3시드 JSON, 비교표, 뉴스1년 표본을 로컬 보존한다. REPORT는 원시 집계·완료 기준·한계, REVIEW_PACKET과 test-results.log는 검증 인계. 사람 플레이테스트·커밋·병합·push는 수행하지 않는다.
