# THE FIRM GitHub 반영 검토

검토일: 2026-11-16 · 대상: 앞서 회수한 ZIP, GitHub 14개 브랜치, 로컬 저장소에 보존된 커밋/미커밋 patch.

## 판정

**ZIP을 풀어 기존 저장소에 덮어쓰거나, 회수한 브랜치를 일괄 main 병합하는 방식은 안 됩니다.** 독립 경영 UI를 별도 실험 폴더에 추가하고, 기획 문서는 Proposed 상태로 선별 보관하는 방식은 가능합니다. World와 GEN은 아래 문제를 먼저 해결하거나 미완료 실험으로 명시해야 합니다.

GitHub 업로드용 별도 브랜치에 작업을 보존하는 것과 main/본게임에 통합하는 것은 다른 판단입니다. 복구 bundle은 백업이며 저장소 루트에 올릴 제품 파일이 아닙니다. 이번 검토에서 GitHub 변경은 하지 않았습니다.

## 직접 확인한 차단 사유

### 1. 최신 경영 소스를 루트에 풀면 기존 설계 문서를 덮어씀

main 파일 트리와 UI 소스 상대 경로를 대조했습니다. `docs/DESIGN.md`가 양쪽에 존재하며 Git blob hash가 다릅니다. 경영 UI의 자체 디자인 문서가 기존 저장소의 디자인 문서를 대체할 이유가 없습니다. 폴더 하나로 격리하면 이 충돌을 피하면서 실행본·테스트·참조의 상대 경로를 보존할 수 있습니다.

독립 경영 프로토타입의 50% 환급은 실험 authored 규칙입니다. 본게임 경제/재판 규칙으로 자동 채택하는 것은 이번 코드 검증으로 정당화되지 않습니다. 직원 4명·최대 업무 7개·5업무일 범위, Godot v0.4 호환 미검증도 유지해야 합니다.

### 2. World 런타임이 Git 저장소 자체를 요구함

`courtroom-prototype/world/generator-source.js`는 실행 시 `git ls-tree`와 `git show`로 커밋 `b6a15ea37ed54864bdb13058a2b3b2874fd4d231`의 생성기 코드를 로딩합니다. 한국어 helper는 별도 커밋 `00b59c6cb086f526f9fa610c03a3404b987e9b18`에서 읽습니다.

로컬 World tip `99d1690`을 `git archive`로 내보내 `.git` 없는 폴더에서 `generator()` 로더 호출을 실행했습니다. **`fatal: not a git repository`로 exit 1**이 재현됐습니다. Git 이력을 갖춘 개발 환경에서 동작하는 것과 GitHub Download ZIP 배포가 가능한 것은 다릅니다. 파일만 복사하거나 얕게 checkout하는 CI에서도 필요한 객체가 없으면 실패할 수 있습니다.

또한 현재 World는 작업 폴더의 최신 GEN 코드가 아니라 고정된 옛 GEN 코드를 사용합니다. GEN 수정과 World가 같은 새 규칙으로 작동한다고 간주하면 안 됩니다.

### 3. GEN 전망 변경은 테스트 통과와 별개로 완료 목표 미달

원격 GEN 기준 `00b59c6`에 회수한 patch와 새 미추적 테스트를 적용했습니다. 관련 테스트 15개는 통과했습니다. 그러나 `generator/report-forecast.js`의 `measure()`를 직접 실행한 결과는 다음과 같습니다.

| 전망 | 건수 |
|---|---:|
| 유리 | 0 |
| 정석 | 0 |
| 변수 | 0 |
| 불리 | 1,000 |

이 1,000건의 실제 결과는 무죄 157건, 다툼이 있는 유죄 754건, 나머지 유죄 89건입니다. 보고서의 세 단계 환산 일치는 89/1000입니다. 이는 승률 정확도 수치가 아니며, 모든 가능한 전략에서도 항상 불리라는 뜻도 아닙니다.

원인은 모든 핵심 쟁점의 자료 보유를 요구하는 새 전망 규칙과, 한 쟁점을 집중 조사하는 기존 표본 정책의 차이입니다. 임계값을 임의로 낮춰 해결할 사안이 아닙니다. **미완료 실험으로 백업 가능하지만, 균형 잡힌 전망 기능이 완성됐다고 main에 넣기는 어렵습니다.**

### 4. 문서 PR은 각각 main에 깨끗하게 병합되지만 서로 충돌함

원격 작업 브랜치 12개를 현재 main과 각각 `git merge-tree --write-tree`로 비교하면 모두 exit 0입니다. 그러나 브랜치 쌍 66개 중 아래 4쌍은 충돌합니다.

| PR 조합 | 충돌 파일 |
|---|---|
| #10 + #14 | ROADMAP.md, docs/CURRENT.md |
| #11 + #14 | docs/CURRENT.md |
| #11 + #9 | docs/CURRENT.md |
| #14 + #9 | ROADMAP.md, docs/CURRENT.md |

단독 자동 병합 가능 판정은 전부 함께 반영해도 된다는 의미가 아닙니다. #14의 현황은 10/14 시점에 고정돼 있어 이후 작업을 누락합니다. 현황 문서는 최신 근거로 하나를 다시 쓰는 것이 적절합니다.

5. DEMO/PLAN/주장 축소/코어루프를 선행 의존성에 맞춰 실험으로 통합하고 브라우저 회귀와 사람 플레이 확인 후 제품 범위를 결정.
