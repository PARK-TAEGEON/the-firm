# TF-UI-001 · 네 단계 정보 설계

기준: PR #12 `d6fa4a303691f60eedf79b829780f443f915e245`. PR #11 `6888997ed3c49c8e11cd419389cb6f0982712598` §1–5는 설계 참고다. A/B/C가 같은 공개 내용·상태·행동을 비교한다. 이 문서는 G1 목업의 정보 구조이며 G3 구현 승인이 아니다.

## 1. 공통 구조

항상 '상담 → 계획 검토 → 법정 진행 → 기록 확인' 중 현재 위치와 다음 주 행동을 표시한다. 단계 표시는 성과/승패 표시가 아니다. 상세 원문은 자료/발언 옆에서 열고 원래 순서·화자·출처를 보존한다. 돌아가기/다시 보기와 새 실행은 다른 행동이다. 법정 화면은 완료된 기록 재생이라고 밝힌다.

상담과 계획에서 미래 판정/답변을 미리 노출하지 않는다. 재면담을 거쳐 알게 된 밀침 인정은 계획에서 처음 등장하며 원본 첫 상담의 접촉 부인과 함께 보존한다. 자료는 '무엇이 확인됨/무엇까지는 모름'을 함께 보여준다. 운반대가 있다는 자료를 손목 상해의 확정 원인으로 바꾸지 않는다.

## 2. 단계별 설계

| 단계 | 플레이어의 질문 | 지금 필요한 정보 | 주 행동 | 보조 행동 | 상세 기록 | 상태의 실제 출처 |
| --- | --- | --- | --- | --- | --- | --- |
| 상담 | 어떤 사건이고 의뢰인은 무엇을 걱정하는가? | 첫 상담 원문 8개, 정민호/변호인 화자, 사무실 배경, 대사 위치, 상해 기소와 계약 걱정이 의뢰인의 말임을 표시 | 다음 대사; 마지막에는 계획 검토로 이동 | 전체 보기, 첫 대사부터 다시 보기 | 8개 대사 전체 원문/화자. 합의에 관한 질문·답변을 삭제하지 않음 | `presentation.consultation.lines/speakers/location`; 상담 로컬 표시 index. CourtRecord 아님 |
| 계획 검토 | 무엇을 승인하고 어디만 고칠 수 있는가? | 검찰 주장, 기존 재면담·자료 검토 상태, 밀침 인정/상해 연결 다툼, 영상·진료 기본 계획, 현장 동선 포함/제외, 내부 비공개 계획이라는 경계 | 내부 계획 승인; 편집 중에는 수정 저장 | 부분 수정/취소, 첫 상담 다시 보기, 자료 원문 펼치기 | 연속 영상/진료기록/현장 동선·재면담의 공개 원문과 제한, 기존 계획의 확인 목적 | `OWNED_PLAN`, `PREP`, 공개 card/client statement. 포함은 UI `useLayout` 선택; 법정 사실/증언 아님 |
| 법정 진행 | 승인한 계획으로 무엇을 했고 상대는 무엇을 다투었나? | 완료 기록 재생 표지, 모두진술→증언→기본 신문→검찰 대응/종결의 실제 순서, 현재 발언의 화자, 해당 계획 항목 | 실제 실행 기록 확인 | 신문 발췌와 검찰 대응 펼침, 관련 근거 열기, 전체 법정 원문 | 원 record ID/seq/kind와 화자별 대사, 관련 card; 생략 없는 전체 원문 | 승인 후 `report.records`; `report.results.*.record`; 새 개입/새 판정/자동 행동 없음 |
| 기록 확인 | 실행·답변·상대 반론·법원 판단은 각각 무엇이 남았나? | 영상/진료/현장의 계획 포함 여부, 실제 수행 여부, 기록된 답변, 검찰 반론, 별도 실험 판결·두 쟁점 결과 | 현재 계획 다시 보기 | 현재 계획에서 부분 수정으로 반대 선택 준비, 관련 원문/전체 기록, 판결 상세 | 질문과 답변의 원 record, 검찰 발언의 원 문맥, `outcome` 쟁점·죄명·주문과 간이 양형 표시 | 계획은 `report.plan`; 수행은 `results.*.performed`; 답변/반론은 records.lines; 판단은 session `report.outcome` |

원본의 '반대 계획으로 비교'는 반대 선택을 계획 검토에 가져오는 동작이다. G1 목업은 현재 계획으로 돌아가 부분 수정하는 경로로 같은 포함/제외 선택을 비교한다. 다시 승인을 누르면 별도 실행이다. 상담 다시 보기·원문 disclosure·기록 순회·화면 재렌더는 사건 기록을 추가하지 않는다.

## 3. 혼동하면 안 되는 다섯 가지

### G1 목업과 실제 런타임의 구분

위 표의 서비스 필드는 원본 런타임의 출처다. G1은 offline로 추출한 fixture.results.*.recordId를 fixture.records에서 조회하며 게임 서비스를 호출하지 않는다. 단계 탭은 네 화면을 비교하는 디자인 탐색 바로가기이므로 실제 승인 전후 접근 게이트의 구현을 뜻하지 않는다. 상담/계획 본문에는 미래 답변·판결을 보여주지 않는다. 기록 화면으로 명시적으로 이동하면 고정 결과 fixture를 보는 것이다. 법정은 진료·영상 발췌를 먼저 보여주고 검찰 재주신문/현장 대응과 전체 발언을 펼친다. 개별 이전/다음 발언 기능은 제안하거나 구현하지 않았다.

| 의미 | 읽기 쉬운 표현 | 허용 출처 | 표시 금지/주의 |
| --- | --- | --- | --- |
| 계획에 포함됨 | 계획 · 포함 / 계획 · 제외 | `report.plan.useLayout` 또는 승인 전 `useLayout`; 고정 기본 계획 | 수행 완료 체크나 유리한 판결 색으로 표시 금지 |
| 실제로 수행됨 | 수행 · 신문함 / 미실행 / 기회 없음 / 실행 오류 | 서비스의 실제 approach/rebuttal record 존재와 `blockedReason`, 결과의 performed | 포함했으므로 실행됐다고 추정 금지. 미실행과 기회 없음의 사유를 분리 |
| 어떤 답변이 기록됨 | 증인 답변 · 서동국 + 원문 인용 | 해당 record의 `lines` 중 화자 ID | 진료기록이 원인 감정이라는 요약, 원하는 답을 얻었다는 성공 배지 금지 |
| 상대가 무엇을 다툼 | 검찰 반론 + 원문/문맥 | redirect 또는 rebuttal 안의 `speaker:'PROSECUTOR'`; 원 seq 참조 | `source`가 defense인 record라고 내부 검찰 발언을 삭제 금지. 반론을 법원 판단으로 표시 금지 |
| 법원이 무엇을 판단함 | 원본 데모의 실험 판결, 죄명/주문/쟁점별 판단 | session `report.outcome.judgment/offense/sentence/issues` | 수행 체크를 사실 인정으로 변환 금지. 원시 trial `verdict.outcome`만으로 최종 무죄/유죄 번역 금지 |

실행 표지는 '계획 ○ / 수행 — / 답변 인용 / 상대 반론 / 판결'처럼 문자와 구조로 구별한다. 색은 보조 수단이며 초록 체크 하나를 포함·수행·유리함 세 뜻으로 쓰지 않는다. 판결은 별도 영역과 제목으로 묶고, 승률/능력치/보너스는 표시하지 않는다.

## 4. 공개 자료와 발언 연결

| 자료/계획 | 계획에서 공개 가능한 요약 | 법정에서 확인할 기록 | 요약이 넘지 않을 경계 |
| --- | --- | --- | --- |
| 의뢰인 재면담 | 어깨를 한 번 민 사실을 인정함 | `OWNED_PLAN.stance`와 실제 opening lines는 구별 | 원본 상담 대사를 고치거나 사건 진실 전체를 공개하지 않음 |
| 연속 영상 | 피해자가 다시 선 뒤 가림막 뒤로 이동; 낙상은 화면 밖 | `approach/A_SIG_CAUSE_SEQUENCE`; 질문과 서동국 답변 | 영상에 없는 낙상 원인을 확정하지 않음 |
| 진료기록 | 손목 타박상을 기록, 별도 원인 감정 아님 | `approach/A_SIG_CAUSE_MEDICAL` | 손상 확인과 특정 원인 입증을 합치지 않음 |
| 현장 동선 | 가림막 뒤 운반대·바퀴 자국; 존재만으로 원인 확정 불가 | `rebuttal/RH_SIG_CAUSE`가 실제 생성된 경우 질문/답변/검찰 반론 전체 | 새 사진 공방·운반대 이동 증언·확정 사고 진실을 발명하지 않음 |
| 검찰 재주신문 | 수행 전에는 아직 해당 발언을 표시하지 않음 | `redirect/RH_SIG_CAUSE`, 서동국 증언과 검찰 질문 | 상대 발언을 판결 요약에 흡수하지 않음 |
| 최종 판결 | 계획 단계에서 숨김 | `report.outcome`와 기록 기반 원본 해석 | 간이 결과를 실제 법률의 검수된 결론으로 제시하지 않음 |

원문 링크는 해당 자료 또는 발언 record ID를 밝히고 바로 펼칠 수 있어야 한다. 기록 전체를 열 때는 원래 `seq`를 유지한다. 요약 화면의 자료별 편집 순서와 실제 공판 순서는 혼동시키지 않는다(실제 기본 신문은 진료기록 다음 연속 영상).

## 5. 상태·긴 내용·좁은 화면

- 포함 후 미실행: '계획에는 포함 / 실제 답변 기록 없음'을 함께 표시한다. 실제 차단 사유가 있으면 그 사유만 읽고, 알 수 없으면 '기록에서 확인되지 않음'이라고 쓴다.
- 기회 없음: 법정 기록에 해당 신문 창/실행이 없음을 설명하며 계획이 실패했거나 증거가 배척됐다고 단정하지 않는다. 고정 두 정상 경로에서 발생하지 않는 예시는 '합성 상태 예시'로 표시한다.
- 오류: 승인 실행 실패는 정상 기록/판결 화면 대신 오류 상태와 계획 검토 복귀를 보여준다. 오류의 시각 디자인만 fixture로 검증하고 실패 판결을 만들지 않는다.
- 긴 한글·긴 발언: 내용 접기와 원문 열기를 제공하되 원문을 줄임표로 영구 절단하지 않는다. 단어 단위 줄바꿈과 긴 ID fallback을 적용한다.
- 390×844: 계획/기록 두 열을 한 열로 재배치하며 다음 주 행동은 손쉽게 접근한다. 관련 자료는 펼침 영역으로 옮기되 원문 접근을 없애지 않는다.
- 1440×900 및 1280×720: 승인·기록 확인 등 주 행동이 초기 화면의 긴 설명 뒤로 밀리지 않게 배치한다. 본문 명암비 4.5:1 목표, 색 이외 라벨, 명시적 키보드 focus, disclosure 상태와 조작 후 focus 복귀를 검증한다. 고정 글자 수 예산은 새 합격 기준이 아니다.

## 6. 세 시안에서 유지할 공통 의미

A는 자료와 계획을 사건철의 양면/주석으로 연결한다. B는 기존 배경과 인물 표식, 발언·상대 반응을 중심에 두고 계획/근거는 보조 영역에 둔다. C는 짧은 사건 요약·단계 흐름·필요할 때 여는 근거를 중심에 둔다. 동일한 여섯 정보 질문과 다섯 상태 의미, 원문과 판결을 보존하며 색만 바꾸지 않는다.

공개 가능한 고정 fixture로 화면을 채우며 footer/안내에 디자인 검증물임을 명시한다. 서비스 실행·범용 판정 엔진·새 개입 창을 목업 안에 만들지 않는다. G2에서는 세 안의 비교판과 추천을 함께 제출하고 사람이 A/B/C 또는 구체 수정점을 결정한다. 응답 전에는 어떤 안도 승인된 것으로 기록하지 않는다.
