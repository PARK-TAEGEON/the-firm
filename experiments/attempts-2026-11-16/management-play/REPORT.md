# THE FIRM · UI 개선 결과

2026-10-27 · Lane: experiment · 기능 기준: 경영 v0.4. 엔진 버전·저장 스키마·경제 규칙을 올리지 않은 UI 개선판이다.

## 1. 바뀐 플레이 경험

첫 화면에서 기한을 확인할 업무와 새 의뢰를 찾고, 바로 담당을 비교한 뒤 하루를 진행한다. 현재 준비 업무의 책임과 오늘 수행할 시간, 실제 기록과 예측을 분리했다. 사건에서는 목록 문맥을 유지한 채 요청·계약·준비·현금·확정 미수를 읽는다. 인계에서는 적용 전에 직원별 오늘 처리량과 전체 업무의 완료·지연·지출 변화를 비교한다.

계약 환급, 무료 인계, 실제 수행의 가용시간 제한, 다섯 번의 하루 진행과 준비 완료의 의미는 기존 v0.4 그대로다. 준비 완료를 승소나 사건 종결로 표시하지 않는다.

## 2. 화면 변경

| 화면 | 구현 |
|---|---|
| 대표 업무실 | 반복 상태 카드와 큰 배너를 줄이고 시간·기한·남은 업무·미수 행, 판단할 의뢰와 병목, 직원 시간 사이드바 배치 |
| 사건 | 세 서류의 선택 문맥을 유지한 요청·계약·준비 문서, 실제 입금과 확정 미수 분리 |
| 인력 | 직원 카드와 정렬 가능한 업무명·담당·남은 시간·기한·예상 완료·조정 표 |
| 배정 | 직원별 처리량 전후, 법률업무 배정 불가 이유, 일정 전후와 지출·현금·미수 비교 |
| 테마·글꼴 | 세 시각 테마, 원래 F0–F9·설치형9개·내장 폰트, 본문/제목/숫자의 로드·대체 표시 |

원본 프로토타입의 Graphite 흑연색·청록, 황동색 워드마크, 세 테마, 목록/상세와 다음 행동 연결을 계승했다. 문서에는 Paper & Ink를 적용했다. A브리핑/B서류철/C편성표는 별도의 화면 구조로 유지한다. 테마·폰트는 `.appearance`, 구조는 `.view`에 저장하며 게임 상태와 분리했다.

본문은 주로14–16px, 보조 정보는12–13px이다. 작은 글씨로 전체를 압축하는 대신 기록·규칙·주간 목표를 필요할 때 펼친다. 표 내부와 긴 모달은 스크롤한다. 390px에서는 상단 주요 행동과 하단 모달 적용 버튼에 접근할 수 있다.

전후 화면은 [UI_COMPARISON.html](docs/UI_COMPARISON.html)에 있다. 같은 초기 상태의1366×768 전후3개 흐름, 개선본 수임/배정/편성/글꼴 및390px 캡처를 포함한다. 긴 이미지는 전체 페이지 캡처이며768px에 모든 내용이 동시에 보인다는 의미는 아니다.

## 3. 실제 검증

| 검증 | 실제 결과 |
|---|---:|
| Python 오프라인 빌드 | exit0 · 9,534,771bytes |
| Node 회귀 | 46/46 PASS |
| 기존 브라우저 | 20/20 PASS |
| v0.4 브라우저 | 11/11 PASS |
| 신규 UI 브라우저 | 16/16 PASS |
| 화면/모달 너비·행동 | 35건 PASS ·1366×768,1440×900,390×844 |
| 원본 전략 비교 | 70조건+70재실행,12,699검증,실패0 |
| v0.4 전략 비교 | 64조건+64재실행,14,035검증,실패0 |
| 기본 오프라인 실행 | 오류0·외부 요청0 |

`node tools/play-verify.cjs --browser`의7개 명령 그룹이 모두 exit0이다. 기능 검증93개와 전략 반복 검증은 별도로 센다. 온라인 폰트 로드 버튼을 명시적으로 눌러 실패시키는 검사는 외부 요청을 별도 기록했으며 기본 오프라인 요청0과 구분한다.

조회·정렬·테마·글꼴·A/B/C·미적용 초안·취소에서 저장 문자열이 보존된다. 수임·배정·5일 진행은 변경하지 않은 엔진 결과와 일치한다. 원본0.3과 실험0.4의 내보내기·가져오기·새로고침도 확인했다. 실제 내장 가변 폰트와 환경에 설치된 Noto Sans/Serif, 미로드 후보의 역할별 대체 표시를 확인했다. 원격 폰트의 온라인 성공 로딩을 검증했다고 주장하지 않는다.

프로젝트 루트의 재현 명령:

```text
python tools/build.py
node tools/play-verify.cjs --browser
node tools/capture-ui.cjs
python tools/package-ui.py --baseline-zip <입력ZIP> --out <출력폴더>
```

이 환경에서는 Windows의 `python` 별칭 대신 설치된 Python3.12.14 실행 파일을 썼다. Playwright1.62.1과 설치 Chromium1243을 사용했다. 별도 모듈 위치는 `CODEX_PRIMARY_RUNTIME_NODE_MODULES`, 브라우저는 `FIRM_CHROMIUM`으로 지정했다. 정확한 결과는 `test-results.log`,신규 근거는 `docs/ui-improvement-qa/result.json`,독립 검토는 `docs/UI_IMPROVEMENT_REVIEW.md`다.

### 입력과 범위 보존

GitHub main `30dc3b25fa7cef6a600a689cd0b1a1cac49cd1d8`의 파일228개 목록을 `docs/github-file-inventory.json`에 기록하고 AGENTS·게임헌법·CURRENT를 읽었다. 이전10월25일 로컬 실행본은 입력v0.4와 SHA256이 같았다. 정확한 경로·범위는 `docs/local-reference-check.json`에 있다. 독립 소스에는 `.git`이 없으며 원본 작업본·미커밋 파일을 수정하지 않았다. Git diff 대신 입력ZIP 대비 `docs/ui-source-diff.patch`와 바이트 비교를 사용했다.

엔진 SHA256: `a288d83b8981dfe5b61b0f95dc700617d84ef0a7082d94e6dbe0c9b4f6019abb`.

최종 HTML SHA256: `db0aac8a264ecdf3a75f5343a0e03f9df51e5c713c46a343e616dc9939455727`.

패키지 생성 시 엔진·RULES·원래 자산·Godot를 입력ZIP과 바이트 비교하고 ZIP무결성과 포함 실행본 일치도 검사한다. 결과는 `docs/ui-provenance.json`에 남긴다. Git push와 외부 배포는 수행하지 않았다. 입력 지시서·원본 프로토타입·폰트·출처와 라이선스를 소스ZIP에 보존한다.

실제 패키지 검사에서 고정 대상24개 파일이 모두 입력과 동일했다. 소스ZIP을 별도 폴더에 풀고 다시 빌드한 HTML도 납품 실행본과 바이트 단위로 같았다. ZIP CRC,원본 프로토타입·폰트 후보·전후 비교·OFL 포함도 통과했다. 근거는 `docs/delivery-validation.json`이다.

## 4. 남은 판단

기능 검증과 화면 가독성 검수는 완료했다. 사람의 재미·선호 검증과 최종 테마 확정은 하지 않았다. 현재4직원·최대7업무·5업무일 고정 콘텐츠이며 장기 경영·새 재판·새 Godot 동작은 범위 밖이다. 작은 화면의 비교표는 내부 가로 스크롤,긴 문서와 인계 상세는 세로 스크롤이 필요하다.

사람에게 확인할 질문은 세 개다.

1. 첫 화면에서 위험 하나와 다음 행동을 설명할 수 있는가?
2. 인계 전후를 보고 비용과 기한 중 무엇을 택했는지 설명할 수 있는가?
3. 보고를 읽고 다음날/다음판 배정을 바꾸고 싶은가?
