# 완료 기준

## 입력과 디자인 계승

- [ ] 기존 UI 프로토타입과 글꼴 후보를 직접 확인했다.
- [ ] 기존 시각 테마 A/B/C와 현재 구조 A/B/C를 구분했다.
- [ ] 기존 프로토타입에서 계승한 레이아웃·테마·폰트 요소를 명시했다.
- [ ] 각 외부 레퍼런스에서 가져온 요소와 가져오지 않은 요소를 설명했다.
- [ ] 원격 이미지의 실제 확인 여부와 폰트 로딩 여부를 구별했다.

## 주요 흐름

- [ ] 업무실에서 다음 행동과 당일 위험을 찾을 수 있다.
- [ ] 사건 상세에서 계약·준비·기한·담당·미수를 문맥을 잃지 않고 읽는다.
- [ ] 두 직원을 비교하고 배정 변경의 이득과 대가를 읽는다.
- [ ] 초안 취소·테마·폰트 변경 후 게임 상태가 그대로다.
- [ ] 하루 진행과 보고가 실제 엔진·실제 수행 기록에 연결된다.
- [ ] 수임 전 환급 조건, 기한 당일 정산, 결산의 현금/미수 분리가 유지된다.
- [ ] 원본0.3 및 실험0.4 저장의 내보내기·가져오기·재실행이 유지된다.

## 실제 가독성

- [ ] 1366×768·1440×900에서 글자·버튼·중요한 금액·업무명이 잘리지 않는다.
- [ ] 390px에서 핵심 행동과 모달 적용 버튼에 접근한다.
- [ ] 핵심 정보를 읽기 위해 브라우저 확대를 강요하지 않는다.
- [ ] 표의 열·행·단위·숫자 정렬이 일관된다.
- [ ] 상태를 색 하나로만 표현하지 않는다.
- [ ] 선택한 폰트가 실제 로드됐는지, 대체 폰트인지 확인했다.

## 상태·검증·납품

- [ ] 기존 엔진 규칙과 저장 schema/version을 유지했다.
- [ ] 기존 미커밋 변경을 보존했다. 저장소가 없으면 없다고 기록했다.
- [ ] 기존 회귀를 실행했고 실패가 있으면 원인·남은 항목을 숨기지 않았다.
- [ ] UI 구조 변경 때문에 테스트를 수정할 때 게임 결과 기대값을 바꾸지 않았다.
- [ ] 실행 HTML·수정 소스·전후 화면·검증 로그를 전달했다.
- [ ] REPORT.md·REVIEW_PACKET.md·필요한 디자인 문서를 갱신했다.
- [ ] 새 경제·전문능력·평판·재판·Godot 시스템을 추가하지 않았다.
- [ ] 재미를 사람이 검증했는지 기능·가독성 확인과 구별했다.

참고: 기존 v0.4의 검증 기록은 Node46개·브라우저31개 통과, 원본70조건 및 새64조건 반복 검증 통과다. 이는 과거 기준선이다. 새 UI 변경 후 실행하지 않은 검증을 새 결과로 재사용하지 않는다.
