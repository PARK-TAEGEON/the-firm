## 2026-10-27 현재 작업 계약

사용자 승인: 직전 권고를 이행하되 현실 모사보다 경영 시뮬레이션의 재미에 집중한다. 개발자 자료를 조사하고, 병목 발견 → 배정 조정 → 결과 확인 → 같은 조건 재도전을 실제 웹 플레이에 드러낸다. 아래 범위의 규칙은 실험용 authored 규칙이며 production DEC가 아니다.

- Owns: 이 독립 실험의 `src`, `tests`, `tools`, `docs`와 루트 문서. 기존 Git 작업본·재판·Godot는 읽기 전용이다.
- 구현: 원본과 구분되는 계약 미이행 환급 실험, 실제/예상 경영 지표, 배정 전후 영향 요약, 당일 병목과 행동 연결, 첫 주/현금 압박 재도전 선택.
- 보존: 원본 보수·업무비·요구시간·가용시간, 무료 인계, 과다 배정 허용, 실제 수행 기록, 구버전 저장과 원본 비교 경로.
- 새 실험: 윤지훈의 준비 보고를 계약 기한까지 완료하지 못하면 착수금의 50%를 한 번 환급한다. 0·25·50·100%는 별도 비교 설정이며 최종 밸런스 확정이 아니다. 플레이용 현금 압박 선택은 시작 현금만 60만원으로 바꾼다. 20만원은 동시 목표 달성이 불가능한 별도 스트레스 검증에만 남긴다.
- 제외: 평판·채용·월급·대출·파산·법정 결과·장기 캠페인·Godot 이식. 자동 최적 배정과 새 난수도 넣지 않는다.
- 파일 담당: 엔진 담당은 engine.js/새 엔진 테스트, UI 담당은 ui.js/style.css/template, 실험 담당은 별도 실행기와 CSV/JSON, 브라우저 담당은 새 테스트, 주 담당은 빌드·문서·패키지. 같은 파일의 병렬 편집을 금지한다.

완료 기준: 원본 회귀 유지, 환급·예측·저장 불변식 검증, 동일 초기 조건 전략 비교, 실제 브라우저 주요 흐름·작은 화면 확인, 조사 근거와 사람 플레이 질문 3개 이하를 보고한다. 자동 검증 통과를 재미 입증으로 표현하지 않는다.

산출물: 실행 HTML, 소스 패키지, `PLAY_REPORT.md`, `docs/management-research.md`, `docs/play-experiments.*`, 재실행 테스트 및 `REVIEW_PACKET.md`.

## 2026-10-25 후속 감사 계약 — 완료된 이전 작업
현재 사용자 요청에 따라 이 디렉터리의 실제 경영 규칙·전략·저장/진행 오류를 검증하고 재현된 오류만 수정한다. 최대 2시간, 마지막 15분은 검증·정리. 원본 경제 수치 변경, 재판 확장, Godot 본이식과 기존 Git 작업본 변경은 제외한다. 엔진 담당은 src/engine.js, UI/빌드는 주 담당, 전략 담당은 별도 tools/docs, 독립 검토는 검토 문서만 작성한다. 산출물은 AUDIT_REPORT.md, REVIEW_PACKET.md, test-results.log, 재현 스크립트, CSV/JSON이다.

## 목적
사용자가 승인한 수임 검토 → 배정 → 시간 진행 → 준비/경영 보고를 실제 상태 변화로 연결하고, 같은 상태를 브리핑·서류철·편성표의 세 구조로 검토한다. 전체 제품이나 기존 재판 통합 완료를 주장하지 않는다.

## 범위
이 독립 디렉터리의 웹 실험 서비스·UI·테스트·자산·Godot 읽기용 대표 화면만 작성한다. 원본 첨부 파일과 기존 PARK-TAEGEON/the-firm 저장소의 코드·브랜치·재판 엔진은 수정하지 않는다. 기존 규칙의 고정 시간 한도·실행 전 산출물 금지·계약/청구/입금 구분을 유지한다. 미정 수치와 스케줄링은 RULES.md에 실험용 authored 규칙으로 기록한다.

## 완료 기준
1. 세 구조가 같은 상태·동일한 행동을 공유한다.
2. 수임 수락/거절, 배정/우선순위, 실제 시간 소비, 청구/입금, 일별 보고가 연결된다.
3. 실패한 명령은 상태를 바꾸지 않고, 같은 현금 입금이 중복되지 않는다.
4. 오프라인 HTML에서 실행하고 저장·복원·JSON 내보내기를 사용할 수 있다.
5. Godot는 동일 snapshot을 읽는 실제 Control/Theme 화면으로 재현한다. 경영 시뮬레이션을 중복 구현하지 않는다.
6. 1440×900, 1366×768, 작은 창에서 주요 흐름을 검수한다.
7. 실제 테스트와 미검증 항목을 REPORT.md에 남긴다. 사람 플레이 판단과 최종 시각 방향 선택은 후속으로 남긴다.
