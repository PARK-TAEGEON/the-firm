# THE FIRM v0.3 — 경영 규칙과 전략 검증

검증 대상은 2026-10-25 생성된 `THE_FIRM_Management_Play_v0.3_Source.zip`의 독립 실험본이다. 기존 Git 저장소의 production 경영 시스템이 아니다. 분석은 `src/engine.js`를 Node로 직접 호출했으며, 다른 경제 모형이나 임의의 실패·벌금 규칙을 사용하지 않았다.

## 핵심 발견

1. **현금만 보면 업무를 덜 수행하는 전략이 유리해질 수 있다.** 원본 수치에서 모든 업무를 저비용 변호사 한 명에게 몰아준 실행은 2/7 업무만 완료하고 사건 2건을 미완료로 남겼지만, 마감 현금은 2,350만원이었다. 고정 분산은 7/7 업무·3건 준비를 완료하고도 2,323.6만원이었다. 착수금은 준비와 무관하게 지급되고, 미완료·지각의 후속 비용이 없으며, 실제 일한 시간만 비용으로 차감되는 현재 규칙의 결합이다. 기록 오염 오류가 아니라 경제 설계 후보이므로 원본 수치는 유지했다.
2. **현금과 준비 성과를 별도로 평가해야 한다.** 모든 기한을 지킨 인계 경로는 현금 2,188만원과 확정 미수금 120만원을 남겼다. 고정 분산은 현금 2,323.6만원이지만 업무 3개가 기한을 위반했다. 이 둘의 현금 차이 135.6만원 중 120만원은 주간 끝의 입금 시점 차이이고, 나머지 15.6만원은 업무비 차이다. 미수금을 현금으로 합쳐 표시하면 유동성 차이를 숨긴다.
3. **전문분야·능력 차이는 구현되지 않았다.** 합법적인 직무와 가용시간·비용 외에는 담당자 생산성이나 결과가 바뀌지 않는다. 기한 준수 경로는 여러 번의 무료 인계에 의존한다. 현재 인계 무료는 문서에 명시된 실험 규칙으로, 악용 버그로 취급하지 않았다.
4. **기존 수입은 기존 준비 완료와 분리되어 있다.** 기존 미수금 450만원은 미완료 여부와 무관하게 day2에 입금된다. 이는 이미 청구된 과거 매출이라는 가정이므로 오류가 아니다. 그러나 이 5일 결과만으로 장기 수익성·반복 수임의 최적 전략을 주장할 수 없다.

원본 규칙 문서와 위 실행 규칙 사이의 경제 수치 불일치는 찾지 못했다. 보고에 언급된 5일 경영 루프는 실제 엔진 호출로 재확인했다. Godot는 이 비교에서 호출하지 않았으며 웹 snapshot을 읽는 대표 화면이라는 범위는 기존 문서와 코드 구조에서만 확인했다. 다른 담당자의 오류 수정 결과는 별도 `ENGINE_AUDIT.md`를 따른다.

## 동일 초기 조건의 5일 비교

`ready`는 준비 완료이며 사건 종결이 아니다. ‘지각 업무’는 한 번이라도 기한 내 미완료 보고에 포함된 서로 다른 업무 수다. 각 전략은 동일한 원본 day0 상태에서 시작하고 실제 지원 명령만 실행했다. 신규 수임 확대는 의뢰 1건을 받는 선택까지만 뜻한다.

| 전략 | 마감 현금 | 확정 미수금 | 준비 완료/미완료 사건 | 완료 업무 | 지각 업무 | 실제 수행 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 신규 거절·기본 배정 | 20,456,000 | 0 | 2 / 0 | 4 / 4 | 2 | 36h |
| 신규 수락·기본 배정 | 22,284,000 | 0 | 2 / 1 | 6 / 7 | 3 | 51h |
| 신규 수락·박서윤 집중 | 23,500,000 | 0 | 1 / 2 | 2 / 7 | 6 | 20h |
| 신규 수락·고정 분산 | 23,236,000 | 0 | 3 / 0 | 7 / 7 | 3 | 52h |
| 신규 수락·기한 준수 인계 | 21,880,000 | 1,200,000 | 3 / 0 | 7 / 7 | 0 | 52h |
| 분산 배정·마감 우선순위 | 22,036,000 | 1,200,000 | 3 / 0 | 7 / 7 | 2 | 52h |
| 분산 배정·신규 보수 우선순위 | 23,236,000 | 0 | 3 / 0 | 7 / 7 | 3 | 52h |

마감 우선과 보수 우선은 **동일한 분산 담당 배정에서 우선순위만 바꾼 비교**다. 마감 우선은 남은 기한 1일 이내=높음, 2일 이내=보통, 그 외=낮음이다. 보수 우선은 신규 사건 업무=높음, 기존 업무=낮음이다. 고정 분산과 보수 우선은 이 초기 조건에서 결과가 같았다. 모든 기한 준수 경로는 `RULES.md`의 공개된 인계 경로를 그대로 재현했다. 어떤 전략도 전체 가능한 행동 공간의 전역 최적해라고 주장하지 않는다.

## 별도 조건·경제 수치 실험

원본 파일·기본 수치를 변경하지 않았다. `validateState`가 이미 허용하는 초기 snapshot 필드만 바꿔 동일 엔진으로 실행했다. 이 설정 변경은 일반 플레이 버튼이 아니라 **실험용 입력**이다. 처리시간 조정은 새 수임으로 생성되는 업무까지 첫 날짜 진행 전에 동일 비율을 적용하며 정수 시간으로 올림한다. 운영비·선행 조건·보상 생성 규칙은 그대로다.

| 조건 | 실행으로 확인된 변화 | 해석의 한계 |
| --- | --- | --- |
| 초기 현금 20만원 | 모든 비교 전략에서 적어도 1일 음수. 신규 거절은 2일 음수·최저 −548,000원, 고정 분산 수락은 1일·−534,000원. 이후 예정 입금으로 양수 회복 | 부족해도 작업이 중단되지 않는 원본 규칙. 대출·파산 생존 실험이 아님 |
| 모든 직원 capacity −1h/일 | 7개 실행 모두 준비 완료 사건 0건. 수락 시 요구 52h 대비 전체 capacity가 50h이므로 3건 전체 준비 완료는 총량상 불가능 | 다른 배정으로 일부 사건은 완료될 수 있음. 모든 전략이 똑같이 나쁘다는 뜻이 아님 |
| 모든 업무 기한 day2 이내 | 고정 분산의 지각 업무 3→4, 기본 수락 3→6. 고정 계획의 현금은 동일 | 기한 자체는 비용/수익/작업 순서를 바꾸지 않음. 마감 우선 휴리스틱은 더 좋은 결과를 보장하지 않음 |
| 시간당 업무비 75% | 고정 분산 현금 23,802,000원 > 집중 23,700,000원으로 순위 역전 | 낮은 업무비는 방치 유인을 줄였으나 구조적 후속 결과를 대신하지 않음 |
| 시간당 업무비 150% | 고정 분산 22,104,000원 < 집중 23,100,000원 | 처리할수록 비용만 커지는 구간에서 집중·미완료의 현금 이점 증가 |
| 신규 보수 50% | 고정 분산 21,436,000원 < 집중 22,300,000원 | 착수/잔금을 모두 50%로 변경. 수임 시장·수요 반응은 없음 |
| 신규 보수 150% | 고정 분산 25,036,000원 > 집중 24,700,000원으로 순위 역전 | 완료 잔금 가치가 늘어나는 조건에서만 이 비교의 순위가 바뀜 |
| 요구시간 75%, 올림 | 기본 수락도 7/7 완료·지각0, 현금23,893,000원. 고정 분산23,752,000원보다 높음 | 기한 압박을 일괄 완화하면 배정 판단이 덜 필요해질 가능성. 재미는 사람 검증 |
| 요구시간 125%, 올림 | 모든 비교 실행에서 준비 완료 사건0건. 총 요구66h, 원래 capacity70h | 총량 여유가 있어도 선행 의존·담당 쏠림으로 비교 계획은 막힘. 전역 불가능을 증명한 결과가 아님 |

각 10개 조건마다 7개 전략을 실행했으며, 시나리오 간 결과는 같은 초기 조건 비교로 섞지 않았다. RNG와 현재 시각을 사용하지 않아 seed는 `null`이다. 최초 baseline 실행은 70회 + 동일 명령 재실행 70회, 12,698개 assertion, 실패0이다. 수정 엔진의 재실행 수와 SHA-256은 `audit-strategies.log`를 따른다.

측정한 **고정 분산 대 박서윤 집중** 두 경로의 현금 차이는 잔금 120만원과 추가 업무비 146.4만원에서 나온다. 배정·처리시간·입금 시점이 그대로라면, 업무비 배율을 `c`, 신규 보수 배율을 `f`라고 할 때 분산의 현금 우위는 `1,200,000 × f − 1,464,000 × c`원이다. 다른 값이 원본이면 업무비가 약81.97% 미만이거나 보수가122% 초과일 때 이 **두 고정 경로 사이의 현금 순위**가 역전된다. 이 식은 기록된 두 경로의 원장 차이를 설명하며, 새로운 시뮬레이터나 전체 전략의 최적성 증명이 아니다.

## 재실행과 산출물

프로젝트 루트에서 Node.js로 실행한다. 추가 패키지·네트워크가 필요 없다.

```sh
node tools/audit-strategies.cjs
```

수정 전 결과와 상태·명령·보고까지 동일한지 함께 검증하려면 다음을 실행한다.

```sh
node tools/audit-strategies.cjs --compare docs/audit-strategies-baseline.json
```

수정 후 실행에서는 70개 결과의 실제 상태·명령·일일 보고가 수정 전과 전부 동일했다. 정상 플레이의 경제 동작이 유지되고 저장 무결성 검사만 강화됐음을 확인하는 근거다. 수정 엔진 SHA-256과 비교 결과는 JSON/log에 함께 저장된다.

- `docs/audit-strategies.csv`: 70개 전략/조건의 현금·준비·기한·직원별 시간 지표.
- `docs/audit-strategies.json`: 엔진 SHA-256, 조건, 초기 상태 hash, 모든 명령 trace, 날짜별 실제 보고, 업무별 완료일.
- `docs/audit-strategies.log`: 실행 수·assertion 수·실패 수.
- `docs/audit-strategies-baseline.*`: 수정 전 원본 엔진에서 실행한 결과. 원본 엔진 SHA-256 `7f3402c767aaa2bb53f6de7da5e3b69b220c671753c07b0d5ef2d2bafffbc1a6`.

수정 전 보존 엔진을 별도로 지정하려면 `--engine`에 프로젝트 루트 기준 경로, `--out`에 출력 접두사를 준다. 저장된 baseline JSON의 engine_path는 최초 실행 당시 경로이며 정확한 버전 식별자는 SHA-256이다.

```sh
node tools/audit-strategies.cjs --engine tests/fixtures/engine-before-audit.cjs --out docs/audit-strategies-baseline-replay
```

검증 스크립트는 모든 결정 상태에서 예측을 **이후 배정이 그대로라는 조건의 실제 실행**과 대조하고, 원본 상태 불변성, JSON roundtrip 후 다음 날 결과, 동일 명령 재실행 결정성, 종료 후 추가 진행 거부를 확인한다. 인계 전략의 미래 인계까지 forecast가 예측한다고 가정하지 않는다. 신규 시장·장기 성장·평판·재판 결과·Godot 게임 진행·실제 UI 클릭 체감은 이 실행 실험에 포함되지 않았다.
