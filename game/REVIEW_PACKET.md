# UI 숫자·툴팁 표기 통일

`game/index.html`에서 열리는 12주 위임 화면의 금액, 주차, 기간, 확률과 툴팁을 통일했다.

| 변경 파일 | 내용 |
|---|---|
| `index.html`, `src/format.js` | 단일 포맷 함수 `format(value, kind)`를 브라우저 및 Node에서 동일하게 사용 |
| `src/ui.js` | 대표 설정·사무소·주간 결산·엔딩의 표시 숫자를 공통 함수로 처리. 모든 툴팁은 요약 1줄과 수치 근거 1~2줄 |
| `tests/format.test.js`, `tests/ui-loop.test.js` | 표기 단위 테스트 5개와 12주 화면 회귀 테스트 1개 |
| `test-results.log` | #23 검증 로그. #25에서 추적 제거 |

## 숫자 표기 전후

| 위치 | 전 | 후 |
|---|---|---|
| 화면·툴팁 금액 | 화면 `7,000만`, 툴팁 `70,000,000` | 두 곳 모두 `7,000만`, 억이 있으면 `1억 1,000만` |
| 만원 미만·0·음수 | `550.5만`에 해당하는 화면 값 `551만`, 원 단위 툴팁 `5,505,000`, 0은 `0` | `550.5만`, `0만`, `−1억 1,000만`. 필요할 때 소수 넷째 자리까지 원 단위 보존 |
| 시즌 주차 | `주` / `1/12` | `주차` / `1주차` |
| 사건 기간·경과 | `주` / `3`, 경과 `1/3` | `기간` / `3주`, 경과 `1주 / 3주` |
| 업무 확률 | `65` | `65%` |
| 명성 변화·시드 | `-2`, `시드 1200` | `−2`, `시드 1,200` |
| 직원 배정 칸 | `1/2` | `1 / 2` |

## 툴팁 문구 전후

`⏎`는 줄바꿈이다. 숫자와 사건·업무 이름은 화면 상태에 따라 달라진다.

| 위치 | 전 | 후 |
|---|---|---|
| 시드 | `시드 ⏎ 7` | `플레이 시드 ⏎ 시드 값 7` |
| 주차 | `주 ⏎ 0/12` | `시즌 진행 ⏎ 완료 0주 · 전체 12주` |
| 현금 | `현금 ⏎ 10,000,000 ⏎ 임대 500만 ⏎ 급여 …` | `운영 자금 ⏎ 잔액 1,000만 ⏎ 임대 500만 · 급여 …` |
| 매출 | `매출 ⏎ 0 ⏎ 1억 1,000만` | `누적 매출 ⏎ 현재 0만 ⏎ 위대한 로펌 기준 1억 1,000만` |
| 명성 | `명성 ⏎ 현재 명성 수치 ⏎ T2 15 ⏎ T3 35 ⏎ 42` | `등급별 명성 기준 ⏎ T2 15 · T3 35 ⏎ 위대한 로펌 42` |
| 등급 | `T1 개인 사무소 ⏎ 임대 500만` | `T1 개인 사무소 ⏎ 임대 500만` |
| 수임 사건 | `사건명 ⏎ 의뢰인 한마디 ⏎ 업무명 · 역할 · 능력치(업무마다 한 줄)` | `사건명 ⏎ 난이도 2 · 예상 기간 3주 ⏎ 업무 2건 · 업무명 / 업무명` |
| 착수금 | `착수 ⏎ 5,505,000` | `착수금 ⏎ 수임 시 550.5만` |
| 성공보수 | `성공 ⏎ 7,000,000` | `성공보수 ⏎ 승소 시 700만` |
| 배정 사건 | `사건명 ⏎ 업무명 ⏎ 난이도 2 ⏎ 5주` | `사건명 · 업무명 ⏎ 난이도 2 · 철회까지 5주` |
| 배정 확률 | `업무명 ⏎ 담당자 65 ⏎ 성공 65 ⏎ 부분 20 ⏎ 실패 15 ⏎ 역할` | `업무명 · 담당자 ⏎ 성공 65% · 부분 성공 20% · 실패 15% ⏎ 정확 5 · 피로 0 · 역할 일치` |
| 진행 사건 | `사건명 ⏎ 변론 2 ⏎ 철회 5` | `사건명 ⏎ 주력 변론 · 난이도 2 ⏎ 철회 기준 5주 경과` |
| 직원 능력치 | `정확 ⏎ 5 ⏎ 2/6` | `정확 능력치 ⏎ 현재 5 ⏎ 다음 능력치까지 경험치 2 / 6`. 최대 능력치는 현재 수치만 표시 |
| 직원 피로 | `피로 ⏎ 15` | `직원 피로 ⏎ 현재 15` |
| 직원 배정 칸 | `칸 ⏎ 1 / 2` | `업무 배정 ⏎ 배정 1건 · 정원 2건` |
| 주급 | `주급 ⏎ 1,000,000` | `직원 급여 ⏎ 주당 100만` |
| 소식·판결 | `기사 제목 ⏎ 사건별 서술` 또는 제목만 | `기사 제목 ⏎ 2주차 · 성공보수 700만 ⏎ 명성 +3` |
| 소식·철회 | 제목만 표시 | `기사 제목 ⏎ 5주차` |
| 주간 결산 업무 | `성공 ⏎ 34 ⏎ 65` | `업무 성공 ⏎ 굴림 34 ⏎ 성공 확률 65%` |
| 엔딩 | `보통 ⏎ T1 개인 사무소 ⏎ 명성 12 ⏎ 7,000만` | `보통 ⏎ 종료 12주차 ⏎ 명성 12 · 누적 매출 7,000만` |

수임 툴팁의 의뢰인 한마디는 카탈로그 데이터에 유지했다. 사건별 판결 서술은 주간 결산 본문에, 로펌 등급명은 엔딩 부제에 표시된다.

## 검증

- `cd game && node --test tests/*.test.js`에서 기존 36개와 신규 6개 통과, 실패 0, 종료 코드 0.
- 금액 경계, 음수·0, 만원 미만 정밀도, 주차·기간, 확률 및 일반 숫자 단위를 검증했다. 화면 회귀 테스트는 시드 7로 12주를 진행하며 네 화면의 표기와 툴팁 줄 수를 확인한다.
- 시뮬레이션, 카탈로그 및 밸런스 파일 변경 없음. 명성 42 · 누적 매출 1억 1,000만 조건은 기존 회귀 테스트로 확인했다.
- 수치 계산과 상태 판단은 기존 엔진을 사용한다. 추가 fixture, 구현 보류 항목, 설계 변경 및 범위 밖 변경 없음.

## PR #25 통합 후 점검

- `src/ui.js`는 대표 이름에 `한서진`을 미리 채운다. 이름을 지우고 개업하거나 새 게임을 시작하면 기본 이름을 사용한다. 수임 툴팁의 세 번째 줄은 업무 수와 업무명 목록을 표시한다.
- `src/loop.js`가 내보내는 `T2_REPUTATION`과 `T3_REPUTATION`을 상단 표시줄과 사무실 명성 패널이 공통으로 읽는다. 등급 기준값과 판결·확률·엔딩 규칙은 기존 값을 사용한다.
- `.gitignore`에 `game/test-results.log`를 추가하고 로그를 Git 추적에서 제거했다.
- `tests/ui-loop.test.js`에서 초기 및 재시작 이름, 빈 이름으로 개업, 수임 툴팁의 업무 목록을 확인한다. 등급 기준 회귀 검사는 화면에 전달하는 기준값을 바꿔 두 표시 위치를 확인한다.
- `cd game && node --test tests/*.test.js` 실행 결과 46개 통과, 실패 0, 종료 코드 0. 브라우저에서 시드 7로 [대표 등록](docs/shots/ui-merge-registration.jpg), [사무실 요약](docs/shots/ui-merge-office.jpg), [명성 상세](docs/shots/ui-merge-reputation.jpg)를 확인했다.

## 사무실 책상 v1

- `src/loop.js`가 구매·착석·퇴실을 처리한다. 자리 상한, 비용, 재승급을 포함한 규칙은 [RULES.md](RULES.md)에 있다. 구매 거절 시 현금과 구매 기록을 함께 보존하며 책상과 직원의 착석 관계는 일대일이다.
- `src/ui.js`의 사무실 표지와 책상 버튼을 `src/style.css`, `src/tokens.css`, `TOKENS.md`에 연결했다. 사진 시야, 상판·의자 윤곽과 얼굴로 등급과 착석 상태를 보여 준다.
- `tests/desks.test.js`에서 구매 거절·비용, 단일 착석과 업무 독립, 주간 승강등을 검증한다. `tests/ui-loop.test.js`에는 클릭 뒤 DOM 확인을 추가했다. 기존 테스트의 기대값은 그대로다.
- `cd game && node --test tests/*.test.js` 50개 통과, 실패 0, 종료 코드 0. 시드 8 화면과 등급 경계 테스트 입력은 [REPORT.md](REPORT.md)에 기록했다. 증거 7장은 `docs/shots/office-desks-*`에 있다.

## 사무실 평면도 v2

- `src/loop.js`는 보유 수량과 앵커별 착석 관계를 관리한다. 강등 시 사라진 자리부터, 이어서 알파벳 역순으로 초과 책상을 회수한다.
- `src/floorplan.js`와 `index.html`, `src/ui.js`가 각 등급의 SVG 도면·현장 버튼·책상 관리 메뉴를 연결한다. `src/style.css`, `src/tokens.css`, `TOKENS.md`에 평면도 표현을 반영했다.
- 기존 `tests/desks.test.js`와 `tests/ui-loop.test.js`에서 구매 직후 자동 설치를 전제하던 입력을 구매·자리 선택으로 나눴다. 비용·사건 배정 독립·중복 착석·재승급 조건은 계속 검증한다. `tests/floorplan.test.js`는 설치 한도·회수, 무효 자리, 세 도면의 구성, 강등 회수 순서를 추가 검증한다.
- 54개 통과, 실패 0, 종료 코드 0. 실행 명령과 브라우저 증거는 [REPORT.md](REPORT.md), 배치 규칙은 [RULES.md](RULES.md)에 있다.
