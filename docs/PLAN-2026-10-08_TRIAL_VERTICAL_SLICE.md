# THE FIRM — 비교 리뷰 이후 개발 계획 개편

문서 ID: PLAN-2026-10-08 · 작성일: 2026-10-08
상태: **사용자 합의 방향 기록 / 구현·재미 검증 전**
범위: 개발 우선순위와 다음 vertical slice. Accepted DEC의 전면 개정이나 구현 완료 선언이 아니다. 구체 수치·자동 진행 정책·UI 배치는 후속 실험 계약에서 검증한다.

## 1. 결정과 배경

**날짜 기반 사무실 판에서 사건 하나를 의뢰 수락부터 준비 → 재판 → 결과까지 끝까지 플레이하는 vertical slice를 다음 목표로 삼는다.** 핵심은 전략·전술 수립 보드에서 한 판단이 재판 엔진에 작용하고, 재판 중 상대의 대응과 상황 변화를 읽어 지휘·전술을 수정하며, 그 기록이 결과와 사무실로 돌아오는 구조다.

이번 전환은 **기존 데모 vs 새 독립 프로토타입을 비교 리뷰한 결과**다. 기존 재판 방식은 읽기·수동 조작의 피로와 정답 경로 퍼즐에 가까워졌고, 새 프로토타입은 주장 범위 선택의 가능성을 보였지만 성공 공식이 일찍 드러나며 상대의 전술적 반응이 계획을 바꾸게 하는 힘이 부족했다. 기존 데모의 버튼 수만 줄이거나 독립 실험의 공방 수만 늘리는 것으로 해결하지 않는다.

방향의 출처는 사용자 요청과 [「데모 리뷰 feedback」 대화](chatgpt-conversation://6ac745ce-3fd0-83ec-bcdb-da63f7c8e28e)다. 그 대화에 공유된 독립 실험 리뷰는 서로 다른 경로 2회 완주·일부 인정 경로 추가 확인을 보고했다. 이는 **전달받은 플레이 리뷰**이며 이번 문서 작성자가 새로 수행한 사람 플레이테스트가 아니다. 기존 데모 소감은 [9월 설계 메모 §2.16](DESIGN-NOTES-2026-09.md#216-데모-플레이-소감과-난이도-원칙-2026-10-08-사용자-플레이-후-논의--방향-합의-수치-미정)에도 남아 있다. 아래 구현 확인은 소스·규칙·리뷰 문서를 읽은 결과이며 재미 평가는 별도로 다룬다.

### 2.1 기존 데모: 살릴 것과 바꿀 것

- 살릴 것: 준비 카드와 공판 기록의 연결, 실제 이의·검사 재주신문·증거 제출 상태, 언어로 표시하는 재판장 메모, 결과별 근거 복기. 반응이 아예 없는 데모가 아니다.
- 소스 근거: [v0.10 engine/trial.js](../courtroom-prototype/engine/trial.js)의 `project`, `resolveApproach`, `pressSucceeds`, `adjudicate`; [통합 RULES §3·14·17](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/demo/RULES.md); [demo-session.js](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/services/demo-session.js)와 [demo-outcome.js](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/services/demo-outcome.js). 준비·입장·신문 결과가 기록 effects와 쟁점 밴드로 이어진다.
- 전달된 리뷰: 신참은 읽을 양이 많고, 베테랑은 막힌 원인을 화면에서 알기 어렵다. 시간 감소·신청 시점·이의가 겹치며 유효 경로가 좁아진다. 준비한 것을 지휘하는 재미보다 올바른 절차 순서를 외우는 부담이 커졌다.
- 변경 의미: 기존의 준비 효과와 공방 기록을 버리지 않고 기본 공방 수행을 전략에 맡긴다. 사람이 직접 고를 일은 의미 있는 목표·근거·대응·위험 판단으로 집중한다. “바닥은 낮게, 천장은 그대로”라는 기존 방향을 유지한다. §2.16의 완화 수치와 특정 경로 제안은 확정·구현된 규칙으로 승격하지 않는다.

### 2.2 독립 실험: 살릴 것과 바꿀 것

- 살릴 것: 무엇을 어디까지 주장할지 판단하는 축, 출처와 비용, 일부 인정·축소의 기록, 상대 반박을 읽고 수정하는 순서.
- [engine.js](https://github.com/PARK-TAEGEON/the-firm/blob/61666f7f55ff4532995609e7e6e9048169de4279/core-loop-lab/engine.js)의 `transition`/`status`: 질문 기여 2·증거 3, 대비 시 1 감소, 강화는 두 출처를 2·3으로 복구한다. 넓은 주장은 연결+5, 좁은 주장은 3이 필요하다. 강화가 상대 대비를 상쇄하면서 원래 성공 절차도 완성하므로 대응을 우회할 동기가 약하다. 이 수치는 **기존 실험 분석용**이며 새 slice의 규칙이 아니다.
- [data.js](https://github.com/PARK-TAEGEON/the-firm/blob/61666f7f55ff4532995609e7e6e9048169de4279/core-loop-lab/data.js): 두 쟁점은 이야기와 대사는 다르지만 동일한 비용·출처·판정 문법을 쓴다. 연결 논증은 미리 작성된 문장이다. 축소 뒤에도 기존 반박 문구가 재사용되어 현재 주장 범위와 어긋날 수 있다.
- 전달된 리뷰: 넓은 주장 경로는 질문+증거+연결, 좁은 경로는 대비되지 않은 증거+축소로 성공 공식이 빨리 보인다. 목표 달성 뒤 회복·유지로 남은 공방을 소진할 수 있다. 일부 인정은 후속 논거의 대가보다 축소·회복으로 느껴졌다.
- [app.js](https://github.com/PARK-TAEGEON/the-firm/blob/61666f7f55ff4532995609e7e6e9048169de4279/core-loop-lab/app.js)와 [REPORT](https://github.com/PARK-TAEGEON/the-firm/blob/61666f7f55ff4532995609e7e6e9048169de4279/core-loop-lab/REPORT.md): 수정 단계의 집중 상시 표시 부족, 비가역 축소 안내의 발견성, 행동 전후 상태 차이 가독성을 검증해야 한다. REPORT도 조기 성공 후 공회전을 위험으로 기록했다. 당시 자동 테스트 통과와 사람 리뷰 완료를 혼동하지 않는다.
- 변경 의미: 반박 문구만 바꾸지 말고 플레이어의 공개 행동으로 상대가 선택할 대응과 남은 위험이 달라지게 한다. 다만 모든 반응에 전술 변경을 강제하지 않는다. 유지도 근거가 있으면 합리적인 선택이어야 한다.

변경하는 것은 **다음 플레이 가능한 산출물과 직접 조작의 단위**다. 기존 법정/새 실험 중 하나를 그대로 본류로 선택하는 대신 통합 경험을 검증한다. 엔진 재사용·이관 방식은 소규모 구현 계약에서 결정한다. 세계·경영 전체 구현을 이 slice의 선행 조건으로 요구하지 않는다.

법정 배경과 검사·재판장 등 인물 삽화는 이번 검증 범위에 포함한다. 이는 CURRENT의 과거 “그래픽 연출 범위 밖”을 이번 slice에 한해 갱신한다. 기존 [§2.11 장소 배경·초상 팩 방향](DESIGN-NOTES-2026-09.md)은 참고하되 최종 아트 제작 방식·자산 목록은 확정하지 않는다. 대체 초상으로 시작할 수 있고 아트는 상태/판정의 입력이 아니다.

| 전략·전술 수립 보드 | 주력/보조 쟁점, 주장 범위, 인정/다툼, 사용할 근거와 연결 논리, 자원 배분, 상대 예상 대응, 대안 | 버전과 근거가 있는 전략. 자동 기본 공방의 대상·행동·순서·중단/개입 조건에 작용하는 입력 |
| 재판 전 소식·대응 | 검사 측 공개 대응·재판부 통지, 합의 제안과 마감, 준비 계획 변경 여부 | 새 정보 출처, 의뢰인 조언·권한, 제출/준비 상태, 변경 전략과 비용. 형사 합의는 피해자 측과의 합의이며 검사 반응과 동일 거래가 아님 |
| 전날/당일 점검 | 새 변화, 미비 자료, 의뢰인 입장, 제출 상태, 우선순위·대안 확인 | 마지막 승인 전략, 남는 위험·미비점. 같은 내용을 재입력하는 의무 체크리스트로 만들지 않음 |
| 재판 화면 | 기본 공방 관찰, 중요한 변곡점에서 유지/강화/축소/전환 등 선택 | 준비 전략에 따른 실제 행동·상대 반응·재판부 절차 처리·공판 기록, 수정 전략의 후속 효과 |
| 결과·복기·허브 복귀 | 판결과 의뢰 목표 달성 정도, 대가, 다음 조치 이해 | 판결 근거, 감사 또는 불만, 명성 변화, 계약상 수익·비용 정산, 항소 가능성/의사·새 일정 소식. 결과를 허브에 한 번 반영 |

사무실은 날짜 진행·소식·일정·최소 자원/업무 현황이 있는 초기 판이다. 날짜는 장식이 아니라 조사 소요·회신·합의 마감·기일·결과 수신을 연결한다. “다음 날/다음 일정”의 정확한 조작과 같은 시각 이벤트 순서는 구현 계약에서 정한다. 여러 화면이 독립적으로 시간을 바꾸거나 결산을 중복 적용하면 실패다.

결과가 항소 가능성을 열면 후속 상담/준비 예정 소식으로 마무리할 수 있다. 항소심까지 플레이하는 두 번째 재판은 이번 범위가 아니다. 명성과 수익은 판결의 승패만으로 자동 보너스화하지 않고 기존 커리어·계약 경계에 연결한다. 감사 표현과 계약 수입도 구별한다.

## 5. 전략 보드·재판 엔진·UI의 함께 검증할 계약

### 전략 보드의 정보와 컨트롤

보드는 이번 slice의 핵심 제작 대상이다. 완성본에서도 재사용할 수 있는 정보 구조·가독성·컨트롤 완성도를 지향한다. **검증 전 기능 목록·버튼 위치·체크박스·막대/슬라이더 배치를 동결하지 않는다.** UI/UX를 메커니즘이 끝난 뒤 붙이는 별도 장식 단계로 두지 않는다.

- 항상 이해할 정보: 의뢰 목표, 쟁점 2~3개, 현재 주장 범위, 연결된 증거/출처, 미해결 반박·공백, 공개된 상대 대응, 남은 일정·자원.
- 의미 있는 입력 후보: 쟁점 우선순위, 인정/다툼 범위, 근거와 논증 연결, 준비/공방 자원 배분, 대안과 개입 정책. 적합한 컨트롤은 각각의 판단 과제로 검증하며 모두를 한꺼번에 구현하지 않는다.
- 선택 전에 비용·제약·포기하는 범위·되돌릴 수 있는지를 표시한다. 사용 불가 사유는 읽을 수 있어야 한다. 변경 직후 무엇이 바뀌었는지 보여준다. 숫자 자원 표시는 허용하되 판정 점수·정확한 승률을 노출하지 않는다.
- “두 근거 연결”이 무조건 적절한 주장을 완성하는 버튼이 되지 않게 한다. 같은 자료로 어느 범위까지 말할지 플레이어가 판단하고, 남은 반론을 확인할 수 있어야 한다. 자유문장 법률 채점기를 요구하는 뜻은 아니다.

### 준비에서 판결까지의 인과 관계

검증 단위는 **준비 입력 → 기본 공방의 행동/기록 → 상대 반응 → 개입/유지 → 수정 이후 기록 → 판결/목표·대가 → 허브 반영**이다. 전략 선택만으로 판정 점수를 더하지 않는다. 실제로 사용한 근거·주장·답변·절차 기록을 통해 판정에 작용해야 한다. 이전의 불리한 기록은 전술을 수정해도 삭제하지 않는다.

최소 대조 실험:

1. 같은 사건·상대·초기 조건에서 준비 전략 A/B를 다르게 한다. 기본 공방의 쟁점·사용 근거·행동/기록 차이를 추적하고, 적어도 한 비교에서는 결과 또는 의뢰 목표/대가가 달라지는지 확인한다.
2. 같은 준비에서 동일한 변곡점까지 진행한 뒤 유지와 전술 수정으로 나눈다. 선택이 후속 대응/기록을 바꾸고 결과 또는 목표 달성에 영향을 주는지 확인한다. 수정이 언제나 상위 선택이면 재설계한다.
3. 동일 기록을 재생하면 동일 판정을 얻는다. 능력·초상·표시 속도만 바꾸어 판결을 바꾸지 않는다. 상대가 미공개 보드를 읽는 편법도 금지한다.
4. 자료는 같아도 주장 범위·논증·실제 사용이 다르면 기록 경로로 차이를 설명한다. 출처를 중복 계산하거나 주장 선택 자체를 새 증거로 만들지 않는다.

### 자동 진행과 핵심 개입

전략에 맞는 기본 공방은 자동으로 수행한다. 주요 변곡점 1~2곳에서는 상황과 선택지를 읽고 유지/변경을 결정한다. 일시정지·이어보기와 속도/요약 조절은 후보이며, 모든 대사에 확인 클릭을 강제하지 않는 것이 목표다. 정확한 자동 정책과 중단 조건은 검증 전 미정이다.

상대는 플레이어가 공개한 주장·자료와 자기 보유 정보에 근거해 대응한다. 예를 들어 한 주장 범위가 흔들렸을 때 다른 남은 근거에 집중할 수 있지만, 이는 구현 후보이지 새 사건의 확정 시나리오가 아니다. 재판부 반응도 검사와 같은 공격 AI로 합치지 않고 절차·기록에 따른 반응으로 표현한다.

목표를 확보했으면 불필요한 고정 공방을 채우지 않고 적절히 마무리할 수 있어야 한다. 추가 이익을 위한 위험한 진행을 제공한다면 실제 선택이어야 한다. 법정 화면은 현재 쟁점·증거·주장·상대 대응·방금 바뀐 상태·남은 위험을 읽게 하고, 배경과 인물 삽화는 이 판단과 몰입을 돕는다. 긴 기록은 펼쳐 보되 핵심 상태와 출처 접근을 숨기지 않는다.

## 6. 범위 제한과 제외 범위

- **사건 하나, 쟁점 2~3개, 중요한 변곡점 1~2개, 복수의 합리적 결과 경로.** 최소 두 접근은 목표/대가가 다르되 납득 가능해야 한다. 버튼 순서만 다른 동일 공식은 복수 전략의 근거가 아니다.
- 기존 대표 사건을 재사용할지와 정확한 변곡점은 첫 계약에서 고른다. 선택 전 새 사건·증인·절차를 추가하지 않는다. 고정 작성한 사건·조건부 반응으로 검증할 수 있으며 범용 AI 완성을 요구하지 않는다.
- 제외: 세계·경영 전체 재설계, 다중 사건 운영, 전체 채용/조직/경제 구현, 장기 NPC 생애주기 통합, 생성기 확장, 전체 항소·환송 플레이, 민사/다국가 팩, 전체 세션 저장 시스템, 최종 플랫폼 확정, 완성형 자산 팩 제작.
- 세계/경영 접점은 기존 구조에 최소 연결한다. fixture나 임시 정산·뉴스를 쓰면 표시하고 실제 시뮬레이션 완료로 보고하지 않는다. 범위 밖 시스템은 삭제하거나 폐기하지 않는다.
- 기존 `index.html`, `trial.html`, 통합 `demo.html`, 독립 `core-loop-lab`, 주장 축소 실험을 비교 기준으로 보존한다. 이번 문서 PR에서는 게임 코드·사건 데이터·판정 수치·아트·기존 테스트를 수정하지 않는다.

## 7. 단계별 구현·검증 계획

각 단계는 다음 별도 실험 작업 계약의 후보 단위다. 이번 문서 커밋이 자동 착수·병합이나 생산 이관 승인은 아니다. UI와 메커니즘은 매 단계 함께 시험하며, 아래 순서는 의존 관계이지 고정 일정/공수 약속이 아니다.

| 단계 | 구현 산출물 | 검증/다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 0. 범위·기준선 고정 | 사건 하나 선택, 쟁점·두 전략 경로·변곡점 설계, 기존 재사용 코드와 미구현 경계, 1페이지 계약 | 비교 커밋·fixture·권한·Owns 명시. 성공/실패 경로를 말로 설명 가능. 세계/경영 전체 설계로 확대되지 않음 |
| 1. 전략 보드와 작은 공방 연결 | 면담/조사 최소 입력, 동작하는 보드와 한 공방, 결과 근거 투영 | §5의 준비 A/B 대조 성립. 사용자가 주력/근거/위험을 화면에서 설명. 보드가 표시 전용이면 중단·수정 |
| 2. 상대 반응과 지휘 | 전략에 따른 기본 자동 공방, 변곡점 1~2, 유지/수정과 후속 처리, 읽을 수 있는 법정 UI·임시 삽화 | 유지/수정 대조 성립. 같은 강화 버튼이 모든 대응을 무효화하지 않음. 축소한 범위와 반박이 정합. 조기 완료 후 공회전 없음 |
| 3. 날짜 기반 한 사건 완주 | 수임→면담→조사→재판 전 반응/합의→점검→재판→결과→허브, 최소 일정·자원 | 실제 날짜/마감·소모 연결. 판결·의뢰인 반응·명성/수익·항소 소식 반영. 앞서 결정한 전략과 수정 근거를 결과에서 추적 |
| 4. 반복 플레이와 다듬기 | 동일 사건의 다른 합리적 경로 비교, 정보 구조/컨트롤/연출 개선, 복기 | 아래 성공 기준을 사람 플레이로 평가. 실패 시 단계 1~3으로 돌아가고 사건 수 확장으로 덮지 않음 |

### 성공 기준과 수집할 증거

- **인과 관계:** 준비 A/B와 유지/수정 대조의 명령·전략 버전·출처·공판 기록·결과를 남긴다. 플레이어가 “어떤 준비와 변경이 어떤 결과를 만들었는지” 설명할 수 있다.
- **상대 대응:** 적어도 한 변곡점에서 기존 계획을 고수할지 다시 고민한다. 선택을 바꾼 이유 또는 유지한 근거를 인터뷰로 확인한다. 텍스트만 새로 나오고 최선 행동이 항상 같은 경우는 통과가 아니다.
- **복수 경로:** 최소 두 합리적 접근의 목표와 대가가 다르고, 특정 지연 제출/버튼 순서만 외우는 것이 유일한 유효 경로가 아니다. 실패·손실 축소도 근거와 만회 판단을 읽을 수 있다.
- **가독성과 피로:** 설명자 없이 현재 쟁점·주장·근거·상대 변화·가능 행동/비용을 찾는지 관찰한다. 실제 플레이 시간, 막힌 지점, 결과에 영향 없는 필수 클릭을 기록한다. 5~10분이라는 독립 실험 목표를 측정된 성과나 새 slice의 확정 길이로 옮기지 않는다.
- **완주와 경계:** 처음 수임에서 허브 복귀까지 이어지고, 날짜·정산이 중복 적용되지 않는다. 아트 없이도 엔진 결과는 같고, 저장되지 않은 값/fixture의 한계가 명시된다.
- **재플레이:** 외부 플레이테스터에게 다른 전략으로 다시 할 이유와 반복 수순이 된 순간을 묻는다. 자동 테스트 통과는 재미 통과가 아니다. 기존 로드맵의 외부 3~5명/출시 일정 판정은 별도 사용자 결정으로 유지한다.

### 실패 기준과 대응

보드를 바꿔도 기본 공방이 같음, 대응을 무시해도 동일 공식으로 해결됨, 성공 후 필수 클릭만 남음, 주장 수정이 과거 불이익을 지움, 숨은 상태를 읽는 상대/설명 불가능한 결과, 읽을 수 없는 핵심 정보, 날짜가 문구뿐임 중 하나라도 핵심 경로에 남으면 통합 경험 검증 실패다. 더 많은 사건·더 긴 공방·아트 양으로 보완했다고 보고하지 않는다. 해당 원인의 메커니즘과 UI를 함께 수정하고 같은 대조를 다시 확인한다.

## 8. 미정과 후속 작업 경계

미정: 사건 선택, 재사용/분리할 엔진 경계, 시간 단위와 동일 시점 순서, 기본 자동 공방 정책·개입 조건, 상대 후보 선택 규칙, 보드 컨트롤/배치, 최소 경제·명성 연결 방식, 삽화 제작 방식, 구체 플레이 시간·수치. 실험값은 후속 Owns 폴더의 RULES에 “실험용 authored 규칙, DEC 아님”으로 남긴다.

기존 DEC의 불변 조건과 충돌할 때만 별도 설계 결정을 만든다. 기존 구현과 미구현 경계를 흐리지 않고, 검증된 부분만 생산 lane으로 이관한다. 문서 검증·변경 범위·회귀 실행 결과는 [이번 REVIEW_PACKET](reviews/PLAN-2026-10-08/REVIEW_PACKET.md)에 남긴다.
