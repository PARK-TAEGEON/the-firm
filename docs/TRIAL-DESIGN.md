# THE FIRM · 재판 경험 설계 현황판

갱신: 2026-10-11 · 문서 v0.2 · 범위: 정민호 사건의 다음 데모 설계

**이 문서는 채팅의 현재 결론을 보는 작업판이다.** Accepted DEC를 대체하지 않으며, 합의·제안·구현·검증은 별개다. 런타임 현황은 [CURRENT](CURRENT.md), 이 문서 작업의 범위는 [DESIGN-SYNC-001](../.agent/tasks/DESIGN-SYNC-001.md)을 따른다. 기본 화면만 읽고, 이유가 필요할 때 아래 상세를 펼친다.

## 60초 요약

**목표:** 이미 있는 사건을 이해하고 변론을 준비한 뒤, 그 계획이 법정에서 실행되는 것을 읽고 필요한 순간에 지휘한다. 게임 전체를 다시 설계하지 않는다.

사무실·수임 → 면담·조사 → **법률 검토 ↔ 변론 계획** → 재판 전 점검 → 자동 공방·선택적 개입 → 결과·사무실

| 구간 | 현재 결론 | 남은 일 |
| --- | --- | --- |
| 사건·조사 | 기존 인물·진실·자료 재사용. 준비 구간 자체는 사용자 평가상 큰 장애물이 아님 | 정보량·공개 시점 다듬기. 사건을 처음부터 다시 쓰지 않기 |
| 법률 검토 | 기본 지식과 알려진 자료의 의미·한계 제공. 계획의 전제도 점검 | 설명·평가 문구와 갱신 조건 검증 |
| 변론 계획 | 입장·근거·실행 방침을 구성. 병행 가능한 방어를 택일시키지 않기 | 직관적인 조작과 실제 행동의 연결 |
| 재판·피드백 | 기존 수사관 신문을 자동 실행 / 알림 / 판단 요청으로 분류함 | 충분히 준비된 경로는 강제 중단 없이 진행 가능. 실제 전술적 갈림길은 아직 미검증 |
| 결과·경영 | 날짜 허브, 수임·외부 비용, 결과 연결은 선행 계획 유지 | 이번 논의로 경제 모델·판정을 재설계하지 않기 |

**지금 열린 질문 `OPEN-01`:** 준비한 계획을 계속할 때와 바꿀 때, 무엇이 달라지고 왜 둘 다 선택할 이유가 있는가?

**이번 검토:** 기존 수사관 신문 분류표를 상세 D에 반영했다. 예상한 반론에 준비한 대응을 실행하는 것은 재결정이 아니라 준비의 보상으로 취급한다. 자료 사용이 항상 타당하면 자동 계획에 포함하며 억지 비용을 붙이지 않는다.

**다음 확인:** 준비 완료 경로의 실행·성과를 읽을 수 있는지 먼저 장면으로 확인한다. 중단 횟수를 채우기 위한 새 증언은 넣지 않는다. 코드 구현·재미 검증은 아직 하지 않았다.

### 두 영역의 역할

| 영역 | 읽는 것 | 제공하거나 정하는 것 |
| --- | --- | --- |
| 법률 검토 | 공개/확보/검토된 사건 자료, 적용 규칙, 현재 계획 | 기본 법리, 가능한 법적 결과와 현재 전망의 구별, 뒷받침되는 전제·미확인 전제·예상 반론 |
| 변론 계획 | 위 검토와 자료, 의뢰인 목표·권한 | 다툴 지점, 주장 범위, 사용할 자료, 확인할 사실, 기본 실행 방침과 필요시 대응 |

자료 변화 → 사건 평가 갱신 → 계획 검토 → 플레이어 수정 → 전제 점검의 흐름이다. 법률 자체가 매번 바뀌거나 의뢰인이 매번 새 비밀을 털어놓을 필요는 없다. 사건 평가가 바뀌지 않으면 창도 억지로 갱신하지 않는다.

합의된 방향은 전문 지식 제공이지 자동 최적화가 아니다. 기초 지식은 별도 해금 퀴즈로 만들지 않고, 복잡한 사건별 연구는 별도 업무로 남길 수 있다. 평가와 예상 반론에는 알려진 자료 범위·조건·출처를 붙이고, 전문가 분석도 판결이나 진실로 승격하지 않는다. 구체적인 분석 규칙·업무량은 아직 확정하지 않는다.

갱신 후보: 중요한 자료 확보/검토, 진술 변경, 공개된 상대 주장, 계획의 실질적 변경. 변경된 요약만 보여주고 전체 법률 보고서를 매번 다시 읽게 하지 않는다.

### 법리의 게임 내 역할

“약한 밀침”, “시간 간격”, “다른 장애물” 같은 직관적 단서를 어떤 법적 쟁점에 연결할지 알려준다. 상해/폭행치상 구별, 고의·예견가능성·인과관계, 증명 기준은 **검수할 주제**이지 이번 문서에서 확정한 적용 법리나 추가 필수 쟁점이 아니다. 새 죄명·형량·판정 수치를 넣지 않는다.

계획 검토는 “현장 사진으로 그 원인까지 단정하려면 무엇이 더 필요한가”를 설명하는 후보 기능이다. “이 전술이 정답”, 정확한 승률, 숨은 사실, 검사 비공개 계획 또는 판사 심증을 보여주지 않는다. 내부 검토상의 인정·공개 법정 입장·의뢰인 동의도 동일 처리하지 않는다.

<summary>상세 C · 논증 구성과 직관적인 조작 후보</summary>

기존 세 선택지의 문제: “밀침 인정”, “엄격한 입증 요구”, “유죄에 대비”는 같은 차원의 대안이 아니다. 입장·목표·우선순위·증거 운용·예비 대응을 구별하되, 구별마다 새 버튼을 만들 필요는 없다. 이미 결정된 내용에서 따라오는 기본 동작은 제안/자동 처리할 수 있다.

**HYP-01 흐름:** 상대의 공개 주장 중 관심 부분 선택 → 관련 자료와 쉬운 법률 검토 확인 → 법정에서 확인할 사실을 계획에 추가 → 예상 대상·자료·행동과 한계를 한두 문장으로 확인.

실험 단위는 `쟁점 / 확인할 사실 / 대상 / 알려진 자료 / 주장 범위 / 실행·중단 방침`이다. 이는 UI·데이터 후보이며 확정 스키마가 아니다. 자유 입력 법률 채점기나 숨은 명제 맞히기를 요구하지 않는다. 미발견 자료를 선택 가능한 카드로 미리 노출하지 않는다.

정민호 사건의 A(영상·진료자료의 확인 범위)와 B(현장 동선·조사 누락)는 병행 가능하다. **A/B 선택 자체, ‘강화’, ‘연결 완료’로 판세를 올리지 않는다.** 실제 사용·답변·반론이 기록에 남은 결과를 평가한다. 순서가 달라질 이유가 없으면 순서 설정도 강제하지 않는다.

공통화할 것은 화면의 정보 역할과 조작 원칙이다. 쟁점·법리·자료·허용 행동·관련 조건은 사건/법체계 데이터로 달라진다. 모든 사건에 인정/다툼/유보를 강제하거나 텍스트를 갈아 끼우는 것만으로 범용 법률 추론이 완성됐다고 주장하지 않는다.

### HYP-02: 완료 표시와 법원 인정을 혼동하지 않기

플레이어 제안은 판사 반응 또는 간단한 체크리스트로 준비의 성과를 보여주는 것이다. 부분 동의만 있었으므로 체크리스트의 채택·표현·위치를 확정하지 않는다.

| 표시 후보 | 뜻 | 뜻하지 않는 것 |
| --- | --- | --- |
| 계획 실행 | 예정된 신문/자료 사용 수행 | 유리한 증언 확보 |
| 증언 확보 | 해당 증인이 실제로 답한 내용 | 법원의 최종 사실 인정 |
| 상대 반론 | 사실의 의미/범위를 다시 다툼 | 앞선 증언 삭제 또는 자동 무효화 |
| 판단 대기 | 기록은 형성됐지만 해당 판단은 아직 없음 | 숨은 패배 판정 |
| 법원 인정 | 실제 판단이 나온 범위의 결과 | 판사 표정·질문만으로 미리 추측한 승리 |

위 상태는 강제 순서나 하나의 진행률이 아니다. 증언 확보와 반론이 동시에 존재할 수 있다. 판사의 질문·절차 판단, 상대 대응, 기록의 변화는 역할이 다른 피드백이며 모두 승리 표시로 합치지 않는다.

기본 화면 후보는 **현재 실행 중 계획 / 방금 달라진 내용 / 남은 반론·계획**이다. 긴 공판 기록은 펼쳐 보고, 주장 수정 후에도 출처와 과거 발언을 보존한다. 점수막대·계획 완료율을 사실인정의 대용으로 쓰지 않는다.

### OPEN-01 검토 1 · 수사관 신문 분류 (2026-10-11)

**상태: 소스 대조에 근거한 설계안.** 사용자는 이 분류 검토를 진행하는 데 동의했다. 아래 세부 정책·자동 이의·표시·재판 변화는 구현되지 않았다. 실제 법률 절차를 검증한 문서도 아니다.

읽은 근거: [사건 데이터 L134~172](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/data/demo-separated-moments.js#L134-L172), [신참·베테랑 수사관 L198~280](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/data/demo-separated-moments.js#L198-L280), [공판 서비스 L34~119](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/services/demo-trial.js#L34-L119), [행동·재반대 L181~255](https://github.com/PARK-TAEGEON/the-firm/blob/288e1e7276a56887f42f7b5f02146c74b583d50d/courtroom-prototype/services/demo-trial.js#L181-L255). 기존 데이터의 사건 진실·기존 답변은 보존한다.

#### 기준 계획 P1

플레이어가 영상·진료자료의 확인 범위를 묻고, 인과관계 주장이 계속되면 현장 동선의 조사 누락까지 확인하도록 준비한 경우다. 목표는 검찰 자료의 설명 범위를 다투는 것이며 운반대가 실제 원인이라고 단정하는 것이 아니다. 수사관 소환, 사용할 자료의 확보·신청·승인, 질문 범위와 실행 가능 여부는 시작 전 점검해야 한다. **좋은 판결을 보장하는 준비 조합이라는 뜻은 아니다.**

| 기존 장면 / 데이터 식별자 | 새 흐름의 분류 제안 | 표시와 실제 남길 내용 |
| --- | --- | --- |
| 수사관의 역할·손목 상처 확인 `D_SIG_INV_1`, `D_SIG_INV_2` | 자동 실행 | 자료 취합 담당이며 손상이 기록됐다는 배경. 계속 버튼 없이 문답 묶음 |

| 베테랑이 먼저 영상 범위를 밝힘 `D_SIG_INV_VIDEO` | 알림 후 계속 | “예정한 확인 일부가 주신문에서 나옴.” 해당 기록을 참조하되 추가 성과로 중복 계산하지 않음 |
| 영상·진료기록 범위 확인 `A_SIG_CAUSE_SEQUENCE`, `A_SIG_CAUSE_MEDICAL` | 자동 실행 + 성과 요약 | 자세 회복, 화면 밖 낙상, 원인 감정 부재에 관한 답변. 법원 인정이나 원인 부정으로 표시하지 않음 |

| 신참의 상처 존재 반복 `RH_SIG_CAUSE` | 알림 또는 묶음 요약 | 이미 남은 손상 사실의 반복. 새로운 위기처럼 중단하지 않음 |
| 베테랑의 “회복만으로 밀침 영향 배제 불가” `RH_SIG_CAUSE` | P1에서는 알림 후 예정 대응 | “예상한 반론. 계획한 현장 자료로 조사 범위를 확인.” 새 결정을 묻지 않되 남은 반론을 숨기지 않음 |
| 현장 동선 확인과 운반대 원인 단정에 대한 반박 `layoutRebuttal` | 사용 가능하고 P1에서 승인했다면 자동 실행 | 실제 답변이 나와야 “그 경로는 검토하지 못했다”를 기록. 원인이 확정됐다는 체크는 금지 |

**자동 실행은 화면 생략이나 조작 금지가 아니다.** 중요한 문답과 계획의 실행은 관찰할 수 있고, 자발적 일시정지·계획 확인은 허용하는 후보로 둔다. 표시 속도·일시정지가 판정에 영향을 주지는 않는다. 알림 역시 매 대사마다 띄우지 않고 실질적인 변화나 성과를 묶는다.

#### 판단 요청의 조건과 같은 사건 내 대조

중단 후보는 **공개된 실제 결과가 아직 실행할 계획의 중요한 전제를 바꿈 + 승인된 대응으로 처리되지 않음 + 플레이어가 바꿀 실질적인 행동이 남음**이다. 반박 대사나 숨은 점수 변화만으로 중단하지 않는다. 계속할 실행이 없으면 미충족 사유를 알리고 정리하며 가짜 선택창을 만들지 않는다.

| 준비/발생 상태 | 처리 제안 | 검토 결론 |
| --- | --- | --- |
| P1의 좁은 주장, 자료 활용과 예상 반론 대응까지 승인 | 자동 실행·성과 알림. 이 신문 구간의 강제 판단 요청 0회도 허용 | 계획이 잘 작동하는 관찰 구간으로 먼저 사용. 0회는 실측치가 아닌 설계상 허용값 |
| 수사관의 원인 의견 답변을 기대한 계획 P2에 베테랑의 이의가 인용됨 `A_SIG_CAUSE_OPINION` | 자료 내용 확인으로 바꾸는 대안까지 승인했다면 자동 전환+알림. 미승인이고 해당 자료·실행 기회가 남으면 방향 변경 판단 요청 후보 | 신참은 역할 한계를 답하고 베테랑은 답변 없이 질문을 막는 차이가 실제 데이터에 있음. 이 차이가 재미있는 갈림길인지는 미검증 |
| 같은 P2에서 이용할 다른 자료·가능한 행동이 없음 | 실패한 확인을 알리고 승인 범위에서 정리 | “추가 증거”를 만들어내거나 클릭을 기다리지 않음 |
| 자료 미신청/증인 미소환, 처음부터 근거 없는 강한 결론 `P_SIG_CAUSE_OVER` | 원칙적으로 재판 전 점검에서 알릴 내용 | 알려진 미비점을 법정의 깜짝 함정으로 쓰지 않음. 공개 목표를 임의 변경하거나 새 지출·권한을 자동 승인하지 않음 |

같은 반론도 계획마다 의미가 다르지만, 모든 순간에 선택의 가치가 비슷할 필요는 없다. 좋은 준비로 한 대응이 명확해진 것은 허용한다. 그러나 상태가 달라져도 동일한 성공 공식만 통하면 전략성은 미해결이다. P2는 기존 분기를 분류하기 위한 대조이며 일부러 나쁜 계획을 짜야 볼 수 있는 이벤트를 권장하는 것이 아니다.

#### 기존 코드와 새 설계를 혼동하지 않을 점

- 기존 `blocked()`/`rebut()`의 `prepared` 차단에는 현장 자료 조기 신청 + 검사의 대비 조건에서 **답변 없이 효과가 0인 분기**가 있다. 이때 위 표의 유리한 수사관 답변은 실제로 나오지 않는다. 모든 준비 경로가 같은 기록을 얻는다고 가정하면 안 된다. 이것을 새로운 좋은 딜레마로 포장하거나 지연 신청을 권장하지 않는다. 해당 효과와 대응 경로는 별도 미결정으로 남긴다.
- `P_SIG_CAUSE_LIMITED`는 기존 `minPoints: 2` 조건이 있고, 주신문에서 먼저 나온 진술은 같은 확인 points를 자동 제공하지 않는다. 중복 질문 생략과 기존 판정 보존을 동시에 주장하지 않는다. 기록을 재사용해 계획 충족을 표시하는 처리는 후속 엔진 연결 때 검증한다. 화면의 체크가 points나 판결을 만들면 안 된다.
- 자동화가 정답표 `proper`, `minPoints`, 미래 답변, 숨은 진실을 읽어 성공 경로를 선택하는 기능이면 실패다. 자동 실행은 공개된 정보와 플레이어가 승인한 범위에서 이루어져야 한다. 일반 이의 판단·변호사 역량 정책은 이번 문서로 해결하지 않았다.
- 현재 수사관 정의는 정해진 답변과 조건부 이의·재주신문을 갖는다. 즉석 새 기억·새 증거·발견 경로를 추가하지 않았다. 마지막까지 반박받지 않는 추상적 “강화”도 넣지 않는다. 기존 DEC-031의 기록 기반·출처 비중첩·능력 직접 가산 금지·법정 RNG 금지는 유지한다.

#### 이번 판단과 다음 장면 확인

**이 장면에서는 준비한 것을 실행하는 재미부터 검증하는 편이 타당하다.** 충분한 준비 뒤에도 매번 새 판단이 필요하도록 만들 근거는 이번 대조에서 확보하지 못했다. 인위적 시간·집중력·랜덤 반전을 붙여 해결한 것으로 처리하지 않는다. 법정 전체에서 의미 있는 개입이 충분한지는 열린 질문으로 남긴다.

표시 초안: “현재 계획: 영상·진료자료의 범위 확인” → “확보: 자세 회복/낙상 미촬영에 관한 답변” → “남은 반론: 이것만으로 밀침 영향이 배제되는 것은 아님” → “예정 대응: 현장 조사 누락 확인”. 확보 문구는 실제 기록이 생성된 때에만 보이고, 예정 대응은 실행 전까지 완료 표시하지 않는다.

다음은 전체 데모의 이 구간에서 P1의 문답·요약만 이어 읽거나 기존 화면에 얹어, **내가 준비한 무엇이 실행됐는지 / 무엇이 아직 미해결인지 / 언제 왜 직접 바꾸고 싶은지**를 확인하는 것이다. 새 독립 게임이나 두 번째 사건을 지금 만들자는 지시는 아니다. P2의 판단 요청은 후속 실행의 실질적 차이까지 정의된 뒤 실험한다.

공통화 후보는 `계획이 확인하려던 내용 → 실제 기록 → 영향받는 후속 행동 → 승인된 대응 유무`다. 장면의 대사와 법적 의미는 사건별로 작성한다. 이후 다른 기존 장면에서도 같은 분류가 되는지 검토하되 수백 사건 범용 엔진 완성을 선행 조건으로 두지 않는다.

사용자 요청: 대화 방식은 유지하되, 정해진 내용을 그때그때 누적해 전체와 놓친 부분을 볼 수 있게 한다. 새로운 관리 앱이나 별도 회의 절차는 이번 범위에 없다.

1. **대화 시작:** 상단 요약과 열린 질문만 확인한다. 옛 결정을 재개방할 때는 바꾸려는 이유를 밝힌다.
2. **한 논점이 정리될 때:** 같은 ID의 상태·결론·이유·연결 구간·검증할 점을 갱신한다. 매번 새 보고서나 별도 DEC를 만들지 않는다. 제안에 침묵했다고 합의로 올리지 않는다.
3. **짧은 체크포인트:** “이번에 정한 것 / 전체에서 달라진 곳 / 남은 질문”만 대화에 남긴다. 저장소 반영 때는 실제 변경·커밋 여부도 구별한다. 자동 백그라운드 동기화는 없다.
4. **구현 전:** 필요한 작은 단위만 별도 Task Contract로 옮긴다. 불변 조건을 바꾸는 경우에만 DEC 판단을 요청한다. 문서 합의와 사람 플레이 검증을 따로 기록한다.

판단에 관한 수정은 이 현황판에서, 상세 선행 근거는 기존 노트에서 관리한다. CURRENT에는 입구만 둔다. ROADMAP은 일정·계약 지도이고 CHANGELOG는 병합 이력이므로 긴 설계 대화의 복사본으로 쓰지 않는다.
