# THE FIRM · 재판 경험 설계 현황판

갱신: 2026-10-11 · 문서 v0.1 · 범위: 정민호 사건의 다음 데모 설계

**이 문서는 채팅의 현재 결론을 보는 작업판이다.** Accepted DEC를 대체하지 않으며, 합의·제안·구현·검증은 별개다. 런타임 현황은 [CURRENT](CURRENT.md), 이 문서 작업의 범위는 [DESIGN-SYNC-001](../.agent/tasks/DESIGN-SYNC-001.md)을 따른다. 기본 화면만 읽고, 이유가 필요할 때 아래 상세를 펼친다.

## 60초 요약

**목표:** 이미 있는 사건을 이해하고 변론을 준비한 뒤, 그 계획이 법정에서 실행되는 것을 읽고 필요한 순간에 지휘한다. 게임 전체를 다시 설계하지 않는다.

사무실·수임 → 면담·조사 → **법률 검토 ↔ 변론 계획** → 재판 전 점검 → 자동 공방·선택적 개입 → 결과·사무실

| 구간 | 현재 결론 | 남은 일 |
| --- | --- | --- |
| 사건·조사 | 기존 인물·진실·자료 재사용. 준비 구간 자체는 사용자 평가상 큰 장애물이 아님 | 정보량·공개 시점 다듬기. 사건을 처음부터 다시 쓰지 않기 |
| 법률 검토 | 기본 지식과 알려진 자료의 의미·한계 제공. 계획의 전제도 점검 | 설명·평가 문구와 갱신 조건 검증 |
| 변론 계획 | 입장·근거·실행 방침을 구성. 병행 가능한 방어를 택일시키지 않기 | 직관적인 조작과 실제 행동의 연결 |
| 재판·피드백 | 자동 실행 + 필요한 판단에 개입. 기록과 변화가 읽혀야 함 | **어떤 변화에 왜 개입하는지 미해결** |
| 결과·경영 | 날짜 허브, 수임·외부 비용, 결과 연결은 선행 계획 유지 | 이번 논의로 경제 모델·판정을 재설계하지 않기 |

**지금 열린 질문 `OPEN-01`:** 준비한 계획을 계속할 때와 바꿀 때, 무엇이 달라지고 왜 둘 다 선택할 이유가 있는가?

다음 논의의 산출물 후보는 **기존 수사관 신문 한 장면의 전후 비교표**다. 새 엔진 착수가 아니다. 현장 자료를 더 쓰는 쪽이 항상 유리하다면, 그 행동을 자동 계획에 포함할지 검토하며 억지 비용을 붙이지 않는다.

### 두 영역의 역할

| 영역 | 읽는 것 | 제공하거나 정하는 것 |
| --- | --- | --- |
| 법률 검토 | 공개/확보/검토된 사건 자료, 적용 규칙, 현재 계획 | 기본 법리, 가능한 법적 결과와 현재 전망의 구별, 뒷받침되는 전제·미확인 전제·예상 반론 |
| 변론 계획 | 위 검토와 자료, 의뢰인 목표·권한 | 다툴 지점, 주장 범위, 사용할 자료, 확인할 사실, 기본 실행 방침과 필요시 대응 |

자료 변화 → 사건 평가 갱신 → 계획 검토 → 플레이어 수정 → 전제 점검의 흐름이다. 법률 자체가 매번 바뀌거나 의뢰인이 매번 새 비밀을 털어놓을 필요는 없다. 사건 평가가 바뀌지 않으면 창도 억지로 갱신하지 않는다.

합의된 방향은 전문 지식 제공이지 자동 최적화가 아니다. 기초 지식은 별도 해금 퀴즈로 만들지 않고, 복잡한 사건별 연구는 별도 업무로 남길 수 있다. 평가와 예상 반론에는 알려진 자료 범위·조건·출처를 붙이고, 전문가 분석도 판결이나 진실로 승격하지 않는다. 구체적인 분석 규칙·업무량은 아직 확정하지 않는다.

갱신 후보: 중요한 자료 확보/검토, 진술 변경, 공개된 상대 주장, 계획의 실질적 변경. 변경된 요약만 보여주고 전체 법률 보고서를 매번 다시 읽게 하지 않는다.

### 법리의 게임 내 역할

“약한 밀침”, “시간 간격”, “다른 장애물” 같은 직관적 단서를 어떤 법적 쟁점에 연결할지 알려준다. 상해/폭행치상 구별, 고의·예견가능성·인과관계, 증명 기준은 **검수할 주제**이지 이번 문서에서 확정한 적용 법리나 추가 필수 쟁점이 아니다. 새 죄명·형량·판정 수치를 넣지 않는다.

계획 검토는 “현장 사진으로 그 원인까지 단정하려면 무엇이 더 필요한가”를 설명하는 후보 기능이다. “이 전술이 정답”, 정확한 승률, 숨은 사실, 검사 비공개 계획 또는 판사 심증을 보여주지 않는다. 내부 검토상의 인정·공개 법정 입장·의뢰인 동의도 동일 처리하지 않는다.

<summary>상세 C · 논증 구성과 직관적인 조작 후보</summary>

기존 세 선택지의 문제: “밀침 인정”, “엄격한 입증 요구”, “유죄에 대비”는 같은 차원의 대안이 아니다. 입장·목표·우선순위·증거 운용·예비 대응을 구별하되, 구별마다 새 버튼을 만들 필요는 없다. 이미 결정된 내용에서 따라오는 기본 동작은 제안/자동 처리할 수 있다.

**HYP-01 흐름:** 상대의 공개 주장 중 관심 부분 선택 → 관련 자료와 쉬운 법률 검토 확인 → 법정에서 확인할 사실을 계획에 추가 → 예상 대상·자료·행동과 한계를 한두 문장으로 확인.

실험 단위는 `쟁점 / 확인할 사실 / 대상 / 알려진 자료 / 주장 범위 / 실행·중단 방침`이다. 이는 UI·데이터 후보이며 확정 스키마가 아니다. 자유 입력 법률 채점기나 숨은 명제 맞히기를 요구하지 않는다. 미발견 자료를 선택 가능한 카드로 미리 노출하지 않는다.

정민호 사건의 A(영상·진료자료의 확인 범위)와 B(현장 동선·조사 누락)는 병행 가능하다. **A/B 선택 자체, ‘강화’, ‘연결 완료’로 판세를 올리지 않는다.** 실제 사용·답변·반론이 기록에 남은 결과를 평가한다. 순서가 달라질 이유가 없으면 순서 설정도 강제하지 않는다.

공통화할 것은 화면의 정보 역할과 조작 원칙이다. 쟁점·법리·자료·허용 행동·관련 조건은 사건/법체계 데이터로 달라진다. 모든 사건에 인정/다툼/유보를 강제하거나 텍스트를 갈아 끼우는 것만으로 범용 법률 추론이 완성됐다고 주장하지 않는다.

[DEC-024 §1~3](https://github.com/PARK-TAEGEON/the-firm/blob/30dc3b25fa7cef6a600a689cd0b1a1cac49cd1d8/DEC-LITIGATION-024_CASE_THEORY_AND_EVIDENCE_SYNTHESIS.md)은 CaseTheory·IssuePosition·ArgumentSelection을 재사용할 근거다. 이 문서는 그 구조나 엔진을 새로 구현하지 않는다.

<summary>상세 D · 재판 피드백과 아직 풀리지 않은 개입 문제</summary>

### HYP-02: 완료 표시와 법원 인정을 혼동하지 않기

플레이어 제안은 판사 반응 또는 간단한 체크리스트로 준비의 성과를 보여주는 것이다. 부분 동의만 있었으므로 체크리스트의 채택·표현·위치를 확정하지 않는다.

| 표시 후보 | 뜻 | 뜻하지 않는 것 |
| --- | --- | --- |
| 계획 실행 | 예정된 신문/자료 사용 수행 | 유리한 증언 확보 |
| 증언 확보 | 해당 증인이 실제로 답한 내용 | 법원의 최종 사실 인정 |
| 상대 반론 | 사실의 의미/범위를 다시 다툼 | 앞선 증언 삭제 또는 자동 무효화 |
| 판단 대기 | 기록은 형성됐지만 해당 판단은 아직 없음 | 숨은 패배 판정 |
| 법원 인정 | 실제 판단이 나온 범위의 결과 | 판사 표정·질문만으로 미리 추측한 승리 |

위 상태는 강제 순서나 하나의 진행률이 아니다. 증언 확보와 반론이 동시에 존재할 수 있다. 판사의 질문·절차 판단, 상대 대응, 기록의 변화는 역할이 다른 피드백이며 모두 승리 표시로 합치지 않는다.

기본 화면 후보는 **현재 실행 중 계획 / 방금 달라진 내용 / 남은 반론·계획**이다. 긴 공판 기록은 펼쳐 보고, 주장 수정 후에도 출처와 과거 발언을 보존한다. 점수막대·계획 완료율을 사실인정의 대용으로 쓰지 않는다.

### OPEN-01: 기존 장면으로 확인할 것

현재 후보는 영상·진료자료 확인 → 수사관 답변 확보 → 검사의 “그것만으로 밀침 영향을 배제할 수 없다”는 대응 → 현장 자료 추가 사용 또는 마무리다. 이것은 기존 사건에서 재사용할 **검토용 장면**이지 재미가 검증된 전술적 변곡점이 아니다.

핵심 공백: 현장 자료가 준비되어 있고 추가 사용에 실질적인 불이익이 없다면 항상 사용하는 편이 나을 수 있다. 이 상태에서는 두 버튼이 있다는 사실만으로 전략성이 생기지 않는다. 또한 이미 계획한 반박이면 자동 대응으로 충분할 수 있다.

다음 장면 비교표에 적을 항목:

| 항목 | 답해야 하는 질문 |
| --- | --- |
| 사전 계획·알려진 상태 | 무엇을 예상하고 어떤 자료를 사용하도록 승인했는가? |
| 실제 반응·새 차이 | 예상과 무엇이 달라졌는가? 기존 계획에 이미 포함된 내용인가? |
| 그대로 진행 | 실제로 어떤 행동과 기록이 뒤따르는가? |
| 개입 | 무엇을 바꾸며 후속 행동·기록·남은 위험은 어떻게 달라지는가? |
| 비교 | 이 변화가 없어도 같은 선택을 했을까? 어느 쪽이 항상 우월하지 않은가? |
| 화면 | 새로 알게 된 내용과 판단해야 할 이유를 짧게 읽을 수 있는가? |

계획이 잘 작동해 유지하는 것도 정상이다. 모든 반론마다 정지하거나 변경을 강제하지 않는다. 자료를 더 쓰는 것이 항상 타당하면 기본 실행에 포함하는 안도 검토한다. 다른 선택을 살리려고 근거 없는 시간·집중력 비용, 마법 같은 새 증거, 숨은 진실을 읽는 상대를 추가하지 않는다.

상대는 공개된 주장·자료와 자신의 적법한 정보만 사용하고, 판사 반응은 최종판결의 대체 신호로 쓰지 않는다. 같은 출처의 반복은 새 독립 성과가 아니다. [DEC-031 §2](https://github.com/PARK-TAEGEON/the-firm/blob/30dc3b25fa7cef6a600a689cd0b1a1cac49cd1d8/DEC-LITIGATION-031_NUMERIC_ADJUDICATION_AND_PROPOSED_DEC_RESOLUTION.md)의 기록 기반·출처 비중첩·능력 직접 가산 금지·법정 RNG 금지는 유지한다.

사용자 요청: 대화 방식은 유지하되, 정해진 내용을 그때그때 누적해 전체와 놓친 부분을 볼 수 있게 한다. 새로운 관리 앱이나 별도 회의 절차는 이번 범위에 없다.

1. **대화 시작:** 상단 요약과 열린 질문만 확인한다. 옛 결정을 재개방할 때는 바꾸려는 이유를 밝힌다.
2. **한 논점이 정리될 때:** 같은 ID의 상태·결론·이유·연결 구간·검증할 점을 갱신한다. 매번 새 보고서나 별도 DEC를 만들지 않는다. 제안에 침묵했다고 합의로 올리지 않는다.
3. **짧은 체크포인트:** “이번에 정한 것 / 전체에서 달라진 곳 / 남은 질문”만 대화에 남긴다. 저장소 반영 때는 실제 변경·커밋 여부도 구별한다. 자동 백그라운드 동기화는 없다.
4. **구현 전:** 필요한 작은 단위만 별도 Task Contract로 옮긴다. 불변 조건을 바꾸는 경우에만 DEC 판단을 요청한다. 문서 합의와 사람 플레이 검증을 따로 기록한다.

판단에 관한 수정은 이 현황판에서, 상세 선행 근거는 기존 노트에서 관리한다. CURRENT에는 입구만 둔다. ROADMAP은 일정·계약 지도이고 CHANGELOG는 병합 이력이므로 긴 설계 대화의 복사본으로 쓰지 않는다.
