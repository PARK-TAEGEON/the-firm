> 목적: 인테리어 시뮬레이터 없이 로펌의 인원·서열·팀·성장을 시각화한다. 공간은 Organization/Business가 결정한 상태를 보여주고, 직원에 대한 의미 있는 관리 명령으로 연결된다.

## 1. 사용자 결정과 이번 문서의 지위

**승인된 방향**
- 로펌 클릭 → **사무실 풍경 + 자리 배치도**가 열리는 화면.
- 자유로운 가구 배치·인테리어 꾸미기는 **기본 게임 범위에서 제외**.
- 채용·퇴사·부서 이동·자리 이동을 화면에 반영.
- 사무실/건물 규모 업그레이드에 따라 공간과 구역 구성이 달라짐.
- 높은 직급에는 개인실, 주니어 어쏘시에이트에는 밀집된 공동 좌석 등 위계가 드러나야 함.
- 직급 체계는 **기본 템플릿 + 성장 후 제한적인 구조 조정**을 권장하며, 구체 권한·밸런스는 미정.

**제안 상태**: 규모별 화면 수, 개별 좌석 수용량, 임대료, 이사 비용, 직급 신설 조건, 승진 룰, 배치 자동화 알고리즘과 UI 배치는 이후 검증할 값이다. 이 문서는 Accepted DEC나 실행 규칙을 새로 확정하지 않는다.

## 2. 기존 시스템과의 소유권 경계

| 영역 | 소유하는 실제 상태 | 사무실 화면에서 하는 일 |
| --- | --- | --- |
| Organization | 소속·직급/역할·직책, 인사·팀, 자격·책임, 가용시간·업무 배정 | 실제 인력·팀 및 좌석 연결 조회, 인사/배정 명령 호출 |
| Business | 임대·이전·공간 용량·고정비·확장 투자 | 장소 변경과 비용/용량 표시, 승인된 계약/확장 명령 호출 |
| Cases / Litigation | 담당 사건, 실제 작업·검토·기일 | 직원 카드에서 담당 사건/업무로 이동 |
| Career / World | 인물 경력·이직·평판·관계·소식 | 프로필로 연결, 소속/이력 변경을 표시 |
| Presentation / UI | 사무실 배경, 배치도, 애니메이션, 좌석별 인물 카드 | 공개 상태를 시각화하고 **명시적 행동 요청** 전달 |

불변 조건:
1. 좌석을 이동했다고 법률 전문성, 현재 업무 진척, 재판 기록·판결, 실제 소속/직급이 바뀌지 않는다.
2. 직급/직책 변경은 Organization의 정식 명령과 인사 이력으로 처리한다. 드래그 앤 드롭은 기본적으로 **좌석 지정** 명령일 뿐이다.
3. 조직 규모나 개인실 자체가 승소율·판사 호의·실력에 직접 보너스를 주지 않는다.
4. 사무실 화면 열기/닫기, 배치도 보기/정렬은 시간·돈·상태를 변경하지 않는다. 계약·이사·인사 변경은 명시적인 서비스 명령으로만 한다.
5. 소속 직원과 좌석은 구별한다. 수용량 부족, 휴직, 외근, 원격/비상주 상태가 직원을 삭제하거나 업무시간을 복제하지 않는다.
6. 아트가 없거나 사무실 화면을 끄더라도 인사·업무·재정과 사건 진행이 정상 작동해야 한다.

## 3. 화면의 기본 구성안

1. **진입:** 사무실/로펌 클릭 → 현재 건물·층·부서·직원 수·가용 좌석·공간 부족 알림을 표시.
2. **풍경 패널:** 현재 규모에 맞는 배경/일러스트 또는 간단한 2D/2.5D 사무실 전경. 실시간 3D 시뮬레이션은 요구하지 않음.
3. **배치도 패널:** 자리·구역에 해당하는 인물 이름/실루엣/직급·부서. 작은 로펌에서는 한 화면, 큰 로펌에서는 층·팀 단위 탭으로 요약.
4. **직원 선택:** 프로필, 담당 사건, 예약된 작업, 현재 업무·휴직·이직 상태, 담당 팀, 좌석 이동과 권한이 허용되는 인사 행동.
5. **관리 조작:** 빈 자리 찾기, 좌석 재배치, 팀/부서 배정으로 이동, 사무실 확장 검토. 대량 채용/이동에는 자동 배치와 일괄 처리 제공.

좌석 아이콘은 장식 요소가 아니라 인물·팀·업무 현황의 **탐색 접점**이다. 성장을 감상하는 풍경과 경영 실무를 확인하는 배치도는 같은 화면 안의 서로 다른 층이다.

## 4. 공간·건물 확장: 표현 예시 (인원 구간/금액 미확정)

| 표현 단계 | 전형적 구성 예시 | 관리의 주된 단위 |
| --- | --- | --- |
| 1인 개업 | 대표 책상, 응접 공간, 기본 서류장 | 개인 |
| 소형 사무소 | 공유 책상, 대표 업무실, 소규모 회의 공간 | 인물·좌석 |
| 중형 로펌 | 파트너 개인실, 어쏘시에이트 공동 구역, 팀/회의실 | 팀·직급·구역 |
| 대형 로펌 | 여러 층, 부서 구역, 파트너·지원 조직별 구분 | 층·부서 중심, 개별 상세 펼치기 |

- 건물 성장의 유효 효과 후보: **수용 가능한 근무 인원, 유지·임대 비용, 회의/접견 시설의 이용 가능 조건**. 이들의 구체 게임 효과는 Business/Organization의 별도 규칙 검증 전까지 TBD.
- 사무실 이전은 경제적 계약 및 일정 이벤트다. 비용이나 준비기간 없이 외형만 바꾸는 무제한 업그레이드는 피한다.
- 높은 직급의 개인실은 **권장 배치/시각적 위계**로 시작한다. 물리적 공간 부족으로 인해 자동으로 개인 능력이 떨어지는 규칙은 만들지 않는다.
- 인원 증가 시 각 사람을 한 화면에서 찾아야 하는 조작 부담을 막기 위해 자동 좌석 배정과 부서 요약을 우선한다.
- 간결한 기본 사무실 레이아웃을 규모별로 몇 개 제공하고, 가구·벽·마감재 등 자유 인테리어 편집기는 만들지 않는다.

## 5. 직급·직책·좌석 구분

| 축 | 의미 | 플레이어가 조절할 수 있는 것 |
| --- | --- | --- |
| **직급 / 고용 지위** | 주니어/시니어 어쏘시에이트, 고용·지분 파트너 등 내부 경력·보상 지위 | 기본 템플릿에서 규정된 범위의 승진/직급 구조; 임금·계약 반영 필요 |
| **직책 / 권한** | 사건 책임자, 팀장, 검토 책임자, 부서 총괄 등 실제 업무 범위 | 적격성·업무량·권한 조건을 충족하면 배정/위임 가능 |
| **좌석 / 구역** | 개인실, 공유 구역, 층·책상 위치와 시각적 표지 | 사용 가능한 공간에서 배정/이동; 법률적 자격이나 사건 권한을 바꾸지 않음 |

**추천: 하이브리드 조직 설계**
- 시작: 대표변호사 → (고용 후) 어쏘시에이트·사무/지원 인력; 파트너 등급과 법무법인 형태는 조직 성장 시 관련 조건 확인 후 개방.
- 중대형 성장: 기본 직급 계층을 제공하되 파트너 비중, 시니어/주니어 비중, 전문팀·검토 책임자 구조를 운영 정책으로 조정 가능.
- 실무상 불가능한 권한·고용 지위를 단순 UI 이름 변경으로 부여하지 않는다. **표시용 직함의 자유 편집**과 **법적·조직적 역할**은 분리.
- 사용자가 커스텀 직급을 무제한 신설하거나 복잡한 결재 규칙을 조합하는 기능은 초기 범위 밖.
- 주니어 책상 밀집, 고참 개인실 같은 연출은 기본 템플릿의 시각적 차등이며 강제 위계·성과 가산이 아니다.

이 구조는 DEC-026의 **TaskOwner/Contributor/Reviewer, 실제 업무시간, 검토 병목**을 대체하지 않는다. 직책이 여러 단계라고 법적 전문성·업무완료·검토 인력이 자동 생성되지 않는다.

## 6. 최소 데이터 계약 후보 (확정 스키마 아님)

- \`OfficeSite\`: site ID, 임대/소유 계약 ref, 공간 타입/표현 단계, 유효 시기, 배경 key.
- \`OfficeZone\`: zone ID, site/층 ref, 팀/권장 직급, 공간/좌석 목록.
- \`SeatAssignment\`: seat ID, person ID, effective_from/to, 요청 주체와 변경 이력; 한 시점 중복 점유 방지.
- \`OrganizationPosition\`: person ID, 조직 ID, 고용 지위·직급·유효기간·계약 refs.
- \`ResponsibilityAssignment\`: 사건/팀의 Lead·Reviewer 등 업무 책임과 위임 범위 참조.
- \`OfficeViewProjection\`: 허용된 사람·구역·배치·상태를 읽기 전용으로 UI에 제공.

외부 인물의 사무실 전체를 자세히 시뮬레이션할 필요는 없다. 다른 로펌은 주요 정보/이력 중심의 축약 표현을 우선한다.

## 7. 검증 게이트와 일정

**현재:** 설계만 저장. P0 판정 엔진 및 P1 재판 수직 슬라이스의 선행 범위를 변경하지 않음.

**이후 단계 후보**
1. **P1 이후 UI/Figma 스프린트:** 소형·중형 로펌의 배치도 와이어프레임. 직원 클릭 → 프로필/업무 → 돌아오기. 가독성 검증.
2. **Organization/Business 연결 실험:** 인사 변동과 좌석 업데이트, 이전 비용과 용량 변경. 좌석 드래그가 역할·업무 변경을 만들지 않는지 검증.
3. **대형 로펌 확장성:** 수십 명 이상에서 요약·검색·자동 배치로 관리가 가능한지 검증.
4. **시각 완성도:** 배경·직급별 구역·이름표·실루엣. 화려한 공간 편집보다 중요한 정보 전달 우선.

필수 테스트: 동일 인물 중복 좌석 배정 차단; 퇴사·휴직·복귀/이전 이력 보존; 대량 인력 이동에도 사건·업무 정보 일치; 화면 열람 무변경; 비용/임대 실반영과 이중 차감 방지; 아트 누락/대체 UI 정상 동작.

**미정:** 직급 수/승진 기준, 구역·좌석 규모, 사무실 이전/업그레이드 비용, 개인실/접견 시설의 실질 효용, 인사권한 UI, 최종 런타임 및 디자인. 미정값을 숫자로 채워 구현하지 않는다.
