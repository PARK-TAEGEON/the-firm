## 1. 이번 사용자 승인 방향

1. **알기 전부터 첫인상이 다를 수 있다.** 명성 있는 변호사의 이름을 이미 알고 호의·경계·경쟁심·반감을 품은 법조인도 있다. 아무런 공통점이나 사적 접촉이 없는 사람도 약한 호감/비호감을 가질 수 있다.
2. 판사·검사·변호사 등은 법정에서 만나고, 반복해 마주치고, 소개·협업·스카우트·이직을 거쳐 관계를 형성한다.
3. **관계 유형 + 인지도 + 호감 + 신뢰 + 이력**을 함께 쓰되, 한 개의 친밀도 숫자가 모든 의미를 대체하지 않는다.
4. 배우는/관찰되는 정보와 인물의 실제 내부 상태를 구분한다.
5. 후속 사용자화 기능으로 **페이스팩과 인물 표시 이름 변경 에디터**를 둔다. 기본 게임의 법적 판정·경력·저장 ID에 영향을 주지 않는다.
6. **명성 별점과 DEC-016의 평판·관계 경계를 양립**시키는 해석은 아래 §2를 따른다.
7. 이번 문서는 설계 기록이다. 0~3, -2~+2 같은 척도 및 실제 변화량·발생률은 별도 플레이테스트 전까지 **Proposed**다.

## 2. 명성 별점 ↔ DEC-016 충돌 해석 (사용자 승인)

### 2.1 유지할 기존 방향

[DESIGN-NOTES §2.9](../DESIGN-NOTES-2026-09.md)의 **0.5~5 별(반 개 단위)** 명성 표시는 유지한다. Career/World가 사건·경력·기사 등 공개 가능 기록에서 도출한 **업계 명성/인지도의 사용자용 요약 표시**로만 취급한다.

- 별점은 공개 업계 평가·인지도에 대한 압축 정보다. **인물의 숨은 법률 능력, 개인별 호감도/신뢰, 무조건적인 사회적 영향력, 법원의 판단점수**를 의미하지 않는다.
- 개인/로펌 명성, 분야별 신뢰도·전문가로서 평판, 개인 사이의 관계는 별도의 의미와 근거를 보존한다. 별점으로 하나의 만능 Reputation/Power 스탯을 만들지 않는다.
- 언론과 커리어 기록에 따른 기대·관심·영입·의뢰/보수의 기회 효과는 **기존 Career/Business/World에서 근거와 경계를 명시한 경우**에만 허용한다. 별 숫자를 신분·권한·법적 결과에 직접 더하지 않는다.
- DEC-016의 dimensioned, provenance-bearing \`ReputationSummary\`는 별점에 흡수되지 않는다. 별은 여러 정보를 보여주는 간단한 헤드라인이고, 상세 프로필에는 출처가 있는 분야·사건·전문성·신뢰 관련 관측 정보를 별도로 제공한다.
- 유명인이어서 초면에 존중하거나 적대할 수는 있어도, **명성값만으로 인간관계 edge·친구관계·판결 유리함을 자동 생성하지 않는다**.

### 2.2 결론

**명성(공개 커리어 요약) ≠ 능력(내부/관측 역량) ≠ 관계(인물별 역사) ≠ 호감 ≠ 업무 신뢰.**

이 해석은 DEC-016의 **single universal reputation/social score 금지**, DEC-031의 **능력·명성·관계의 판결 직접 가산 금지**, 기존 별 UI 결정과 양립시키기 위한 **사용자 승인 설계 가이드**다. DEC-016 원문을 덮어쓰거나 판정 모델을 바꾸지 않는다.

## 3. 인물·관계의 책임 분리

- \`LegalProfessionalIdentity\`: World 소유의 영구 인물 ID; 직역 전환·이직·은퇴 후에도 동일 인물.
- \`RoleProfileHistory\`: 판사/검사/변호사/고문 등 역할별 경력. 이전 직역 능력을 새 직역 능력치로 복사하지 않는다.
- \`ProfessionalRelationship\`: **유형·방향·기간·출처를 가진 관계**. 전 동료+멘토+라이벌 등 복수 관계를 한 쌍에 동시에 가질 수 있다.
- \`InteractionRecord\`: 법정 만남·소개·협업·멘토링·채용 상담 등 실제 접촉 사건. 전체 대화 원문 보관 의무 없음.
- \`ProfessionalInformationItem\`: 플레이어가 알게 된 정보의 출처·관측 시점·유효 시점·불확실성.
- \`PlayerObservedProfessionalProfile\`: 공개/관찰/추정의 표시; 비공개 실제 성향이나 법정 결과를 몰래 노출하지 않는다.

세계의 인구는 주요/일반 인물 간 **관계의 의미/영구 ID 규칙은 같고, 처리 빈도와 묘사 상세도만 달라지는** 구조를 따른다. 1:1 완전 관계 행렬을 모든 NPC에 미리 생성하지 않는다.

## 4. 제안하는 최소 관계 척도 (실험안)

| 요소 | 제안 척도 | 구체 의미 | 정보/결과 경계 |
| --- | --- | --- | --- |
| **인지도** | 0~3: 모름/이름만 앎/직접 만남/반복 교류 | A가 B를 어느 수준으로 인식하는지. A→B와 B→A는 다를 수 있음 | 명성에 노출되거나 법정에서 실제 접촉하면 관측에 따라 상승 가능 |
| **호감** | -2~+2: 강한 반감/반감/중립/호의/강한 호의 | 실제 접촉 후 형성된 개인적 태도; 정보 부족 시 0과 **미형성**을 별도로 표시 | 인지도 또는 별점 자체가 자동 상승/하락값은 아님 |
| **신뢰** | 0~3: 미검증/약한 신뢰/업무 신뢰/깊은 신뢰 | 약속 이행, 협업, 실제 경험에 기반한 **분야·상황별 신뢰** | 법정 증거 신빙성/사실인정 점수에 사용 불가 |
| **관계 유형** | 다중 typed edges | 전 동료, 선후배, 멘토, 라이벌, 같은 사건 상대 등 | 우호/적대 하나로 모든 유형을 덮지 않음 |
| **관계 이력** | 사건·시점·출처 refs | 언제 무엇 때문에 관계가 생기고 바뀌었는가 | 원본 이벤트 보존·현재 요약과 분리 |

척도 자체는 **내부 실험 편의**로만 제안한다. 플레이어에게 “호감 +1” 같은 수치를 반드시 노출하지 않는다. 접근 가능한 관측에 따라 “이름은 들어봤다”, “여러 번 맞붙었다”, “우리의 업무 방식을 신뢰한다”처럼 설명한다.

**방향성:** A가 B를 좋게 평가한다고 B가 A를 좋아할 필요는 없다. 교우/동기 같은 유형은 양쪽으로 성립할 수 있지만 호감·신뢰·인지 수준은 각각 별도다.

## 5. 첫인상 형성 규칙

**정보 노출 → 기대/선입견 형성 → 첫 직접 상호작용 → 경험에 따른 수정** 순서로 처리한다.

- **알려진 사실만 입력:** 해당 NPC가 접할 수 있었던 공개 사건·기사·소개·선행 접촉을 이용한다. 플레이어 명성이 높아도 모두가 그것을 정확히 안다고 가정하지 않는다.
- **성향/가치관:** 전문성 존중, 경쟁심, 보수성, 협업 성향 등 적은 수의 authored 특성에 근거하여 호의·경계·반감·무관심이 나타날 수 있다.
- **이유 없는 반감의 표현:** 플레이어 눈에는 불합리하거나 설명되지 않은 첫 반감이 가능하다. 내부에는 인물 성향과 관측 사건/정보 또는 최초 성향 반응에 근거가 있어야 하며, “반감 +1 확률”이 법적 판단을 바꾸는 시스템으로 이어지지 않는다.
- **초면 인상은 친분과 다름:** 이름만 알고 호의적이라고 \`친구\`/\`신뢰함\` 관계 edge가 자동 생성되지 않는다. 필요하면 \`InitialDisposition\`처럼 **일시적인 태도/기대**를 관계 이력과 별도로 계산한다.
- 명성이 주는 첫인상은 한 방향으로 고정하지 않는다. 높은 명성이 존중·기대·질투·경계·무관심으로 갈라질 수 있으며 구체 분포는 미정.
- 동일 인물·동일 관측 정보/성향/세계 상태에 동일 반응을 얻도록 생성 시드를 관리한다. 플레이어가 화면을 다시 열거나 대사를 재생해서 반응을 다시 굴리지 못하게 한다.

## 6. 접촉·관계 변화 예시

| 실제 사건 | 상태·기록 변화 후보 | 금지/주의 |
| --- | --- | --- |
| 처음 같은 법정에서 마주침 | 인지도·법정 접촉 이력 추가 | 판결 보너스, 즉시 친구 생성 금지 |
| 반복 대립 | 상대 전문성 평가·경쟁 이력/라이벌 관계 후보 | 이겼다고 자동 적대, 졌다고 호의 금지 |
| 공동 사건·실무 협업 | 수행한 업무와 함께 관측 신뢰 변동 후보 | 단순 같은 로펌 소속으로 자동 친밀 금지 |
| 약속 이행 또는 중대한 위반 | 명시적 관계 이벤트와 신뢰 변화 | 과거 신뢰 기록 삭제 금지 |
| 소개·추천·멘토링 | 실제 정보/만남/경력 기회, 멘토링 시간 및 관계 이력 | 공짜 영입·역량 상승·수임 보장 금지 |
| 이직·퇴직·전관 전환 | 소속/직역 프로필 갱신, 기존 관계 유지 | 새 NPC 생성·판사 능력 복사 금지 |
| 오랜 공백 | 일시적 친숙함 약화 검토, 과거 edge/사건 이력 유지 | 무조건/빠른 관계 소멸 금지 |

**결과와 연동할 때:** 판사·검사의 명성, 법정 상대 경험, 관계는 상대의 적법한 준비 행동·공개 정보 접근·직무상 배치/이해충돌 검토 입력으로 이어질 수 있지만, **고정된 동일 증거·기록에 대한 판결·증거 신빙성·법률 기준**을 직접 바꾸지 못한다.

## 7. 게임플레이에서의 쓰임과 경계

가능한 후속 시스템: 합법적인 소개/상담 기회, 채용·이직 접촉, 업계 뉴스 제보 및 공개 정보, 멘토링·교육, 협업 수락, 라이벌 경쟁 서사, 합법적 이해충돌/회피 검토의 **입력**.

각 효과에는 실제 이벤트·업무시간·권한·비용·출처가 필요하다. 관계 edge 존재만으로 사건 수임·직원 성장·전관 판결 특혜를 확정하지 않는다.

- 사례: 전직 동료 → 업계 동향을 들을 기회(허용) / 전직 동료 판사 → 같은 기록에 유리한 판단 +10%(금지).
- 소개 받음 → 실제 의뢰인 상담 기회(허용) / 소개 받아 계약·현금 즉시 생성(금지).
- 신뢰받는 팀원 → 협업 의사/업무 인계 효율 검토 대상(허용) / 신뢰만으로 증거 추가(금지).
- 친분이 있어도 윤리·이해충돌·회피/기피의 실제 법적 판단은 별도 ko 규칙이 마련되기 전까지 자동 처리하지 않는다.

**상호작용 남발 금지:** 법정 한 번 참석하거나 메뉴에서 말 걸었다는 이유로 매번 호감 +1을 주지 않는다. 플레이어가 재판 대신 친구 만들기 반복 노동을 하게 하지 않는다.

## 8. 프로필·페이스팩·이름 편집 (후속 UI/모드)

기존 DESIGN-NOTES §2.13·§2.15의 검색·관심 인물·페이스팩 방향을 계승한다.

### 인물 프로필
- 공개 이력/소속/담당 사건/별 명성/주요 뉴스, 플레이어가 겪은 접촉, **알려진** 관계 유형과 평가를 섹션별로 표시.
- 추정된 성향·능력은 출처와 불확실성(낮음/보통/높음 등)을 붙여 표기. 내부 진실/숨겨진 친분은 자동 공개하지 않는다.
- 판사/검사/변호사와 은퇴 후 고문이 동일 인물 링크·기록으로 이어져야 한다.
- 사건과 기사 속 이름은 프로필로 연결되되, 초상화가 없어도 필수 정보가 읽혀야 한다.

### 페이스팩
- **기본:** 실루엣 대체 초상(현행 메모 방향 유지).
- **풀 배정:** 나이대·스타일 등 표시용 태그를 가진 초상 풀에서 세이브 시드로 결정적 배정. 같은 세이브의 같은 인물은 항상 같은 초상.
- **고정 인물:** 안정된 person ID에 직접 지정한 초상이 있으면 우선 적용.
- 에셋 로딩 실패/미지정이어도 인물 생성·재판·인맥·세이브 시스템이 변하지 않는다.
- 향후 별도의 팩 매니페스트·설치/검증 UI와 Steam Workshop 연동을 검토. 출시 전 라이선스/실존 인물 사진·초상권/명예훼손 문제를 안내하고 안전한 기본 정책을 유지.

### 표시 이름 변경 에디터 (신규 제안)
- 본래의 **영구 person ID, 공식/기본 이름, 이력/판결문/관계 참조**와 플레이어의 **표시용 별칭(alias)**을 분리.
- 사용자가 편집한 별칭은 프로필·UI·게임 내 기사 등 표시 계층에만 적용. 원본 기록의 ID/출처·직업·과거 소속을 수정하지 않는다.
- 저장별 override(권장 기본)와 향후 전역 팩 override를 구분. 동일 인물 다른 세이브의 충돌 및 다른 사람과 이름 중복 문제를 검증.
- 고정 인물에 대한 ID 지정 방식과 생성형 인물의 씨드/ID 안정성 보장을 함께 검토.
- 에디터는 게임 규칙을 수정하는 개발용 NPC 편집기가 아니며, 초상·별칭만 변경한다.

## 9. 개발 순서·검수

**지금:** 문서만 보관. 기존 P0→P1 재판 수직 슬라이스, Accepted DEC 및 법정 판정은 수정하지 않는다.

**후속**
1. WORLD의 인물 ID·이력·정보 공개 범위와 관계 타입을 작은 테스트 fixture로 연결한다.
2. 동일한 판사·검사·상대 변호사를 최소 2~3회 만나는 시나리오로 **첫인상/재접촉/관계 이력**을 검증한다.
3. 소개 1개, 경쟁 관계 1개, 협업 1개 등 **실제 세계 기회만** 만드는 좁은 기능부터 시작한다.
4. 프로필·정보 노출 UI를 Figma 스프린트에 포함시키되, 모든 인물 관계를 메뉴에서 수동 관리하는 의무를 만들지 않는다.
5. 페이스팩 및 별칭 에디터는 기본 관계·ID/세이브 안정성이 확인된 후 별도 구현한다.

**필수 테스트:** ① 같은 seed/관측으로 동일 첫인상, ② 정보 미노출 인물이 명성/친분을 전지적으로 알지 못함, ③ 관계가 한 방향/복수 유형을 지원, ④ 접촉 빈도만으로 호감도 무한 상승하지 않음, ⑤ 이직·은퇴·재진입 후 동일 ID/이력, ⑥ 관계/별점만 바꾼 고정 법정 기록의 판결 불변, ⑦ 사무실/프로필/초상·이름 편집이 게임 상태나 원본 기록을 변조하지 않음, ⑧ 편집/모드 파일 없을 때 정상 대체 표현.

**미정:** 척도 캘리브레이션, 성향 taxonomy, 최초 노출/반감 가중치, 관계 이벤트의 드문 발생·감쇠 규칙, 실제 AI/대화, 경력과 명성 지표 aggregation, 법적 이해충돌 절차, 에디터 폴더/API/플랫폼 구현.

## 10. 관련 자료와 새로 결정한 내용의 경계

- **기존 Accepted:** DEC-016의 persistent identity, typed/directional/multi-edge 관계, 실제 정보 출처/공개 범위, 관계의 비판정 원칙. DEC-031의 direct bonus 금지와 법정 RNG 금지. DEC-017의 숨은 능력과 관측 실력 분리.
- **기존 설계 메모의 사용자 결정:** 명성 0.5~5 별, 활동 이력과 업계 소식, 법조인 검색/관심 인물, 기본 실루엣, 시드/ID 기반 페이스팩, 한국을 닮은 가상 세계.
- **이번 사용자 승인:** 첫인상·친밀도/신뢰의 별도 설계, 별과 DEC-016의 충돌 해석, 별칭 에디터, 법정 만남에서 이어지는 관계의 성장 방향.
- **이번 문서의 실험 가정:** 척도 0~3/-2~+2, 변화값·비율·UX·관계 성장 타이밍. 전부 플레이테스트 뒤 조정 대상.

기존 DEC를 임의로 수정·승격시키거나 WORLD-001 실험 구현을 관계 시스템 완성으로 간주하지 않는다.
