## 1. 모순 (문서끼리 서로 다른 말을 함)

### 1-A. 증거 강도 숫자 합산 — 금지된 방식을 실험 전부가 쓰고 있다 【높음】

| 문서 | 내용 |
| --- | --- |
| DEC-012 L21 | 권장 모델에는 “evidence strength point, 확률, 개수 임계값, 변호사·로펌·판사 보너스, 마지막 RNG가 없다” |
| DEC-012 L148 | “EvidenceUse마다 numeric strength와 부호 — 합산 쉬움 … **Forbidden**” |
| DEC-012 L199 | “evaluator에 lawyer ability를 직접 더하는 것은 **Forbidden**” |
| DEC-007/008/011/013 | 점수 합산 판정 배제(같은 취지) |
| DEC-017 LWP5 | 변호사 능력은 결과에 대한 직접 보정치가 아니다 |

그런데:

- **v0.10 trial**(Claude 제작): 쟁점별 입증 수치 합산 → 입증 ≥5 / 의심 ≤2 밴드로 판결. 판사 메모는 말로만 보여주지만 내부는 숫자 합산이다.
- **GEN-001**: 증거 strength, `strengthRange [3,7]`, 반전 효과가 수치 가감.
- **WORLD-001**: 능력치 ≥ 난이도 판정, 확률 이벤트.
- **DESIGN-NOTES §1.9**(오늘 추가): 능력·복잡도로 전망 3단계 산출.

현재 규칙상으로는 **실험 lane이라 허용**된다(AGENTS.md: 실험 lane은 RULES.md로 자체 규칙 가능, 기존 Accepted 코어는 보존). 하지만 어느 문서에도 “실험의 숫자 모델은 DEC-012와 다르며, 본류 채택 시 어떻게 처리한다”는 말이 없다. 이대로 가면 데모·플레이테스트에서 재미가 확인된 쪽이 숫자 모델인데, production 절차로 넘어가는 순간 Accepted DEC와 정면충돌한다.

**결정 필요 (택1):**
- (a) 숫자 모델은 실험용 근사로만 쓰고, 본류 채택 시 DEC-012 구조(명제·범위·지지/충돌 topology)로 옮긴다. → 이관 비용이 큼. 재미가 숫자 쪽에서 나왔다면 옮기다 잃을 수 있다.
- (b) 플레이테스트 결과가 숫자 모델을 지지하면 DEC-012를 개정(새 DEC로 supersede)한다. “플레이어에게 숫자를 보이지 않는다”는 원칙만 유지. → 추천. 1인 개발 규모에서 DEC-012의 topology 모델은 작성 비용이 매우 크다.
- 어느 쪽이든 CURRENT.md의 Decision Pending에 한 줄 올려 두는 것을 권한다.

### 1-B. 자동 진행 전망 vs 능력 비가산 원칙 【중간】

§1.9는 “능력·사건 복잡도로 계획대로 흘러갈 가능성을 말로 보여준다”고 적었다. DEC-012 L199 / DEC-017 LWP5는 능력이 결과를 직접 바꾸면 안 된다고 한다.
§1.9 본문의 “역배는 주사위가 아니라 공개되지 않은 반전에서 온다”는 DEC-012 정신과 맞는다. 충돌하는 것은 **전망 산출식에 능력을 넣는 부분**뿐이다.
- 조정안: 능력은 “조사에서 반전을 찾아낼 확률”에만 작용하고(간접), 판결 평가는 기록만 본다. 이러면 DEC-017과도 양립한다. 1-A를 (b)로 정하면 문제 자체가 사라진다.

### 1-C. Accepted 결정이 Proposed 결정 위에 서 있다 【중간】

- Proposed(미승인): DEC-014, 015, 016, 017, 022, 027, 028, 029.
- Accepted DEC-018~021은 Proposed 014~017을 전제로 인용하고, Accepted DEC-023~026은 Proposed 022를 전제로 한다.
- 즉 “확정된 결정”의 토대가 미확정이다. 014~017이 뒤집히면 018~021이 근거를 잃는다.
- **결정 필요:** 014~017, 022를 Accepted로 올리거나, 018~021·023~026의 상태를 “Proposed 전제에 조건부”로 표기. 재미 검증 이전에는 후자가 가볍다.

### 1-D. 헌법의 “다음 설계 단계” 【낮음】

`00_GAME_CONSTITUTION.md` L93: “다음 설계 단계: DEC-LITIGATION-009”. 실제로는 DEC-030까지 진행됐다. 에이전트가 헌법을 읽고 009부터 다시 설계하려 들 위험이 있다. 한 줄 수정 권장(“현재 상태는 docs/CURRENT.md”).

## 4. 한국 실무 지식 공백

전 문서 검색 결과(0 = 언급 없음): 증거동의/부동의 0, 국민참여재판 0, 성공보수 0, 국선 0, 공판준비기일 0, 처벌불원 0, 집행유예 0, 변호사법·광고규정 0, 양형 1개 파일, 구속·보석 3개 파일.

게임 재미와 직결되는 순서로:

1. **증거동의/부동의 (형사소송법 318조)** — 한국 형사재판에서 대부분의 서류증거는 피고인 측이 “동의”하면 그대로 증거가 된다. **부동의해야 작성자를 증인으로 불러 신문**한다. 즉 “어떤 증인을 법정에 세울지”는 변호인의 선택이다. v0.10은 증인이 정해져 나오는데, 이 선택 자체가 좋은 전략 레이어가 된다. 준비 단계에 넣기 쉽다.
2. **처벌불원·합의** — 폭행·음주 사건 실무의 핵심은 무죄보다 **합의와 양형**이다. 폭행죄는 반의사불벌죄라 처벌불원이면 공소기각. “무죄냐 유죄냐” 2지선다만 있으면 한국 형사변호 느낌이 약하다. DEMO-001의 결과 분기(합의/감형)와 직결.
3. **양형과 집행유예** — 유죄여도 실형/집행유예/벌금 차이가 의뢰인 만족도의 대부분. 결과 화면에 “유죄 · 집행유예 2년” 같은 층이 필요.
4. **형사 성공보수 무효** — 대법원 2015. 7. 23. 선고 2015다200111 전원합의체: 형사사건 성공보수 약정은 선량한 풍속 위반으로 무효. → **generator는 이미 형사 원형에 `success_pct: [0, 0]`으로 반영되어 있음(확인 완료).** 다만 이 근거가 문서에 없어, 누가 나중에 “형사도 성공보수 넣자”고 하면 막을 근거가 없다. SYS-004에 한 줄 필요. 형사 매출은 착수금 중심 → 경영 밸런스에 큰 영향.
5. **국선변호** — 신입 변호사·소형 로펌의 초반 수입원이자 사건 유입 경로. 세계 시뮬의 “사건 공급”에 들어가야 할 요소.
6. **국민참여재판** — 배심원 설득이라는 전혀 다른 법정 모드. 지금은 범위 밖으로 두되 “있다는 것”은 기록.
7. **공판준비기일** — v0.10의 “준비” 단계에 실제 절차 이름을 붙일 수 있다(쟁점·증거 정리).
8. **변호사법·광고 규정** — 로펌 경영에서 홍보·수임 경로 제한(브로커 금지, 광고 규정). 경영 시스템 설계 시 필요.

**현실 반영 수치**(DESIGN-NOTES §2에 이미 있는 것 외 새로 필요한 것 없음). 공소청 전환(2026-10-02)은 §2에 반영되어 있다.
